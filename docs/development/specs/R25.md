## Invariants (the reviewer checks each)

1. **Visitors and members lose nothing and gain no admin markup.** The HTML and the messages payload for a non-admin carry no admin row, no group id in an admin context, no `admin.panel` keys. The only client code they download in addition is the empty `AdminGroupProvider` (§2.1, a few lines) in `Providers`; the bridge itself renders only when the server says `moderation.isSiteAdmin`.
2. **No DB change, no migration.** New reads only (`count`, `findMany`, `findUnique`). Hide and restore reuse `hideGroup` / `restoreGroup` (`actions/moderation-actions.ts:8,26`) unchanged.
3. **Nothing destructive runs from a menu.** The shield's group rows open the Grupa tab or link to a page; hiding needs a typed reason in the tab; deleting stays in Admin > Moderācija (hide first, delete there), as today.
4. **Laws.** Prisma only in `lib/services/`; the new action starts with `requireSiteAdmin()`, returns `ActionResponse<T>` with uppercase codes; the service throws `ActionError('FORBIDDEN' | 'NOT_FOUND')`; Zod as a value only in `lib/validations/` (the hide form reuses `hideGroupSchema`); no `any`; new constants in `lib/constants/admin-panel.ts`; hide and restore in the tab have an `isPending` guard. **Context Law:** the panel and the shield learn the current group from a context the group layout's own `GroupProvider` feeds (§2.1), never from props through `Header` and never by parsing the URL.
5. **Rows are hidden, never greyed** (AR-51 and the shield alike). A queue row with 0 shows no number but stays (the menu is stable, owner: "global first, stable").
6. **Visual baselines:** only `group-page` at 768, 1280 and 1920 (light and dark) may change, and only in R25-1. Everything else 0 px diff, including `group-page` at 360 (the drawer is closed there). R25-2 and R25-3 change no PNG. No admin screen is added to `tests/visual/`.
7. **The banner gets no share icon** (owner: it stole title room on phones). Dalīties lives only in the left menu, at every width.

## 2. The Grupa tab (R25-2)

### 2.0 Motivation and design alignment

Site-admin rows in a group's menu mix two audiences (owner's note), and hiding through a modal hides the context an admin needs (why, who, what reports). The panel (R23) is already the admin's place on any page, so the group's moderation goes there as a tab. **How the panel learns the group without breaking the Laws:** the panel and the shield are mounted in the root layout and the header, outside the group layout. The group layout already fetches `GroupContext` through `GroupService` and hydrates `GroupProvider` (Context Law). A tiny client bridge inside that provider copies an `AdminGroupRef` (ids, name, two flags) into a root-level context; the panel and the shield read it with a hook. The tab's details come from one admin-only server action that calls one service read (Service, Action Laws), fetched when the tab opens, so a non-admin group page costs nothing more.

### 2.1 State: the current group

- `components/providers/AdminGroupContext.tsx` (new, <= 40): `AdminGroupProvider` (holds `useState<AdminGroupRef | null>`), `useAdminGroup(): AdminGroupRef | null`, `useSetAdminGroup()`. Mounted in `components/providers/Providers.tsx` around the children, next to `AdminPanelProvider`.
- `type AdminGroupRef = { id: string; name: string; href: string; l1Slug: string; slug: string; hidden: boolean; canHide: boolean }` exported from that file. `canHide = !hidden && user.role !== 'OWNER'` (today's rule, `GroupMenuActions.tsx:56`).
- `components/admin-panel/AdminGroupBridge.tsx` (new, <= 30, `'use client'`, renders `null`): reads `useGroupContext()`, sets the ref in an effect keyed on `id, name, hidden, canHide`, and on cleanup clears it only if the stored id is still its own (soft navigation group → group must not race to `null`).
- Mount it in `app/[locale]/[l1Slug]/group/[groupSlug]/layout.tsx` inside `GroupProvider` (line 34), only when `group.moderation.isSiteAdmin`. Server decides; non-admins never render it.
- After hide/restore the tab calls `router.refresh()`; the layout re-renders, `GroupProvider` gets the new `moderation.hidden`, the bridge updates the ref, the shield's row flips (R25-3).

### 2.2 Constants and the tab id

### 2.3 Data: one service read, one action

- `lib/services/group-panel.ts` (new, <= 110, a helper module like `group-card.ts`): `getGroupPanel(groupId: string, adminId: string, locale: string): Promise<GroupPanelData>`. Checks the site role (`isSiteAdminUser`, as `feedback.service.ts:188` does) and throws `ActionError('FORBIDDEN')`; unknown id throws `NOT_FOUND`. One `findUnique` with `select` (name via the existing localized-title helper the group service uses, `type`, `createdAt`, `hiddenAt`, `hiddenReason`, `hiddenBy.name`, owner's name from the OWNER membership, member count by `_count` on approved memberships as `GroupService` counts them, L1 title and L2 titles in `locale`), plus in `Promise.all`: open reports `report.findMany({ where: { targetGroupId, status: 'PENDING' }, orderBy: { createdAt: 'desc' }, take: GROUP_PANEL_REPORTS_MAX })` with `report.count` of the same where, and `ModerationService.listActions(GROUP_PANEL_LOG_MAX, groupId)` (`moderation.service.ts:194`, reuse, do not copy).
- Returns `GroupPanelData`: `{ id; title; href; theme: { l1: string; l2: string[] }; status: { hidden: false } | { hidden: true; reason: string | null; by: string | null; at: Date }; ownerName: string | null; createdAt: Date; memberCount: number; isPrivate: boolean; reports: { total: number; items: { id: string; reason: string; createdAt: Date }[] }; log: AdminActionEntry[] }`. Never a raw Prisma payload.
- `actions/admin-panel-actions.ts`: add `getGroupPanelData(groupId: string, locale: string): Promise<ActionResponse<GroupPanelData>>`: `requireSiteAdmin()`, parse `groupId` with a schema from `lib/validations/admin-panel.ts` (`groupPanelInputSchema = z.object({ groupId: z.string().min(1) })`, or the shared id schema if one exists: grep `lib/validations` first), call the service, `handleActionError` on throw. No `revalidatePath` (read).
- Dates cross the action boundary as `Date` (server actions serialize them); format on the client with `useFormatter().dateTime`.

### 2.4 Tab listing and the empty case

So the tab shows on group pages, and stays listed off a group page only while it is the open tab (the selection never vanishes under the admin). Off a group page the body is one line `admin.panel.group.none`. `PanelTopBar`'s `showPause` (line 81 of the render) is false for `group` as for `translate` (no page clicks to pause). `hint.group` follows the pattern at line 90.

### 2.6 Hide and restore in the tab

- **Visible, `canHide`:** a `Textarea` (`components/ui/Input`) labelled `moderation.reasonLabel`, placeholder `moderation.reasonPlaceholder`, hint `moderation.reasonHint`, 3 rows; under it one filled destructive button `moderation.hideGroup` (`press`, the destructive variant the `ConfirmPopover` uses). Validate with `hideGroupSchema` (`lib/validations/moderation`) on submit; show the field error inline. Submit calls `hideGroup(id, reason, locale)`; `isPending` disables the button and the field. Success: toast `moderation.hiddenToast` (§5), clear the field, `router.refresh()`, refetch. The typed reason is the deliberate step: no confirm pop-over (hiding is undoable). One sentence above the field, `text-meta`: `admin.panel.group.hideNote` (owner is notified, the group can be restored).
- **Visible, the admin owns it:** no form; `text-meta` line `admin.panel.group.ownGroup`.
- **Hidden:** one button `moderation.restore` (outlined, not destructive), `isPending` guard, then refresh and refetch. Deleting is not here: one `text-meta` line `admin.panel.group.deleteWhere` with a link to `/admin?tab=moderation` (where `deleteHiddenGroup` lives today).
- **Links (always):** Labot tēmu → `/admin/groups/<l1Slug>/<slug>/categorization`, Labot grupu → `<href>/settings` (today's `GroupMenuActions.tsx:87-88`, labels `adminTools.fixCategorization`, `adminTools.editGroup`).
- **Focus requests (§2.2):** `hideReason` focuses the textarea, `restore` the restore button, `reports` scrolls the reports section into view and focuses its label (`tabIndex={-1}`). On phones the sheet opens to at least half (`usePanelSheet`, same call the Dizains pick uses) so the field is visible.
- Escape (`usePanelEscape`): inside the textarea it leaves the field first (R23 behaviour, unchanged).

## Risks

- **Stale or racing group ref.** Soft navigation between two groups unmounts one bridge after the next one mounts; clear only when the stored id is your own (§2.1). Response races in `GroupTab`: drop a response whose id is not the current ref id.
- **`group` cookie off a group page.** Handled by keeping the tab listed while open (§2.4); do not silently switch tabs on the client (the server-rendered mode would disagree with the panel).
- **Messages payload.** If `moderation`/`adminTools` are pruned for the client, the tab shows raw keys; §2.7 checks it. Non-admins must not start receiving `admin.panel`.
- **Visual drift.** Moving Ziņot changes `group-page` at 768+ only; any change at 360 means the drawer or banner moved: fix, don't accept.
- **Bundle for non-admins.** `AdminGroupProvider` is the only shared addition; the bridge, the tab and the menu sections stay in admin-only chunks (`AdminPanel` is `dynamic`, the shield renders for admins only).
- **Counts cost.** Four counts per menu open, none per page view. If an admin opens the menu repeatedly the module cache shows numbers at once; no polling.
