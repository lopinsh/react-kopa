# R26 spec · Unsplash banner picker

Spec for R26, written 26 Oct 2026 against `main` at `63cd6ff` (R25 live). Source: the owner's decisions of 26 Oct (below), the earlier note in `docs/archive/execution_handoff_2026-10-15.md` item 3.6 (line 721), build plan C5 (`docs/development/build-plan.md` section 6). There is no drawing; the picker is composed from existing parts (`Modal`, `PictureBox`, `Input`, `Button`, `TextLink`), the same way as [AR-02](../redesign.html#AR-02).

**Owner decisions of 26 Oct, applied as written**
1. One picker replaces the plain banner URL field in the group wizard, the group settings (`BasicsSection`) and the event form (`WhatWhenStep`).
2. It opens on about 8 curated Unsplash photos for the group's main category (L1), plus a "no image" tile, which means the category-colour fallback.
3. "Meklēt Unsplash" inside the picker runs through a server action. The key `UNSPLASH_ACCESS_KEY` is server-only. Without the key, search is hidden and the curated photos still work.
4. The Unsplash API rules apply: hotlink the image URLs, call `download_location` on the server when a photo is picked, and show "Photo by X on Unsplash" with UTM links in the picker and wherever the banner is shown big.
5. The raw URL field stays, for site admins only, behind an "Papildu" disclosure.
6. Nothing is uploaded. Only the URL and the credit are stored.

**Size and split.** About 30 files, too many for one build of about 80 tool calls. It ships as two builds, each reviewed and pushed on its own. R26-2 starts only after R26-1 is pushed, because both touch `messages/*.json`.

## Invariants (the reviewer checks each)

1. **Taxonomy Law.** No image URL ever goes into the layout's `<style>` block (build plan section 6, "Taxonomy Law with images"). Images are `<Image>` elements. The fallback tile keeps reading the server-set `--accent`/`banner-tint`. Inside the picker, the "no image" tile may scope `--accent` to its own box (AGENTS.md Law 3, live preview).
2. **The key never reaches the client.** `UNSPLASH_ACCESS_KEY` is read only in `lib/services/unsplash.service.ts` (`import 'server-only'`). No `NEXT_PUBLIC_` variant exists. The page passes only a boolean `searchEnabled` to the form.
3. **Raw URLs are a site-admin power, enforced on the server.** A non-admin can only save `null`, an `images.unsplash.com` URL, or the value that is already stored (so legacy picsum banners survive an unrelated settings save). Hiding the field is not the check.
4. **Credit follows the URL.** When a raw URL is saved, or the image is cleared, both credit columns become `null` in the same write. A credit is never shown without its image, and an image from the picker never loses its credit.
5. **Existing banners are untouched.** No data migration. Seed and demo banners (picsum) keep rendering as today, with no credit line.
6. **The event rule stays (AR-59).** An event without its own image shows no picture on its page. The event panel keeps falling back to the group's picture (`event-panel.ts:93`), and the credit falls back with it.
7. **Action Consistency / Defensive Coding.** Every new action returns `ActionResponse<T>` with uppercase codes. Every picker button and the search submit are disabled while pending. Shared Zod schemas live in `lib/validations/banner.ts`.

## 0. Motivation and design alignment

- **Service Law.** Unsplash is an outside data source, so its client lives in `lib/services/unsplash.service.ts` next to the other services. Actions only check auth and map errors. The URL and permission rule is one helper (`assertBannerAllowed`), called by the group and event services. It is not repeated in actions or components.
- **Constants Law.** The curated list is static data in `lib/constants/unsplash-curated.ts`. The UTM source name and the image parameters live in `lib/constants/index.ts` (`UNSPLASH_UTM`, `BANNER_IMG_PARAMS`).
- **Reuse.** The dialog is `Modal` (a sheet on phones, per behaviour "Pop-ups"). Tiles are `PictureBox` at 16:9. The fallback tile reuses `GroupPicture`'s tint and icon pattern, extracted into a shared `PictureFallback`.
- **Handbook.** Colour means category (design "Colour"): the no-image tile is the only tone in the picker, and buttons use the site colour. Voice: the credit is a plain fact line, `text-meta` and muted.

## 2. Data and migration (R26-1)

`prisma/schema.prisma`: `Group` (line 148) and `Event` (line 269) each get two nullable columns next to `bannerImage`:

```prisma
bannerCreditName String?  // photographer's display name, as Unsplash returns it
bannerCreditUser String?  // Unsplash username (profile link is built from it)
```

Migration `npm run db:migrate -- --name add_banner_credit` is additive and nullable (expand only), and works with the running version. No backfill. No photo id is stored: tracking happens at pick time (section 3), not at save.

**Stored URL.** Build it from the photo's `urls.raw` (which keeps Unsplash's `ixid`) plus `BANNER_IMG_PARAMS = 'w=1600&h=900&fit=crop&crop=entropy&auto=format&q=75'`. This is a 16:9 crop that also covers the 5:2 card band through `object-cover`. It matches the owner's "urls.regular + crop params" (regular is raw at `w=1080`; raw lets us set the crop and size). Curated entries build the same URL from their `photo-…` path. The thumbnail in the picker uses `w=400&h=225&fit=crop&crop=entropy&auto=format&q=60`. `next.config` already allows `images.unsplash.com` (remotePatterns), and `getSmartImageUrl` leaves it unproxied.

## 3. Server: service, actions, validation (R26-1)

**`lib/validations/banner.ts` (new, ≤ 60 lines)**
- `bannerCreditSchema = z.object({ name: z.string().trim().min(1).max(80), username: z.string().regex(/^[A-Za-z0-9_-]{1,40}$/) }).nullable()`
- `unsplashSearchSchema = z.object({ query: z.string().trim().min(2).max(60), page: z.number().int().min(1).max(10) })`
- `unsplashPhotoIdSchema = z.string().regex(/^[A-Za-z0-9_-]{6,20}$/)`
- `lib/validations/group.ts:44` and `event.ts:31` add `bannerCredit: bannerCreditSchema.optional()`. `bannerImage` keeps its URL rule. Both form-value types gain `bannerCredit`.

**`lib/banner.ts` (new, ≤ 70 lines, no Prisma)**
- `unsplashImageUrl(rawOrPath, params)`, `unsplashProfileUrl(username)`, `UNSPLASH_HOME_URL`. The last two append `?utm_source=${UNSPLASH_UTM}&utm_medium=referral`, with `UNSPLASH_UTM = 'ejam_kopa'`.
- `isUnsplashImageUrl(url)`: the host is exactly `images.unsplash.com`.
- `assertBannerAllowed(next, { current, isSiteAdmin })`: allows `null` or `''`, an Unsplash URL, `next === current`, or any URL for a site admin. Anything else throws `ActionError('BANNER_URL_NOT_ALLOWED')`.

**`lib/services/unsplash.service.ts` (new, ≤ 120 lines, `import 'server-only'`)**
- `isUnsplashSearchEnabled(): boolean` returns whether the key is set.
- `searchPhotos({ query, page }, locale)` calls `GET https://api.unsplash.com/search/photos?query=…&page=…&per_page=8&orientation=landscape&content_filter=high` with the headers `Authorization: Client-ID <key>` and `Accept-Version: v1`, and `lang=lv` when the locale is `lv` (Unsplash supports `lang`). It returns `{ photos: UnsplashPick[]; hasMore }`. Results with `premium` or `plus` true, or whose `urls.raw` host is not `images.unsplash.com`, are filtered out. `UnsplashPick = { id; url (stored form); thumb; alt; credit: { name; username } }`. Fetch uses `cache: 'no-store'` and a 6 s `AbortSignal.timeout`. A missing key, a non-2xx response or a timeout throws `ActionError('SEARCH_UNAVAILABLE')`, and a 403 with `X-Ratelimit-Remaining: 0` throws the same.
- `trackDownload(photoId)` sends `GET https://api.unsplash.com/photos/${id}/download` with the key. Without a key it does nothing. Errors are logged (`console.warn`) and swallowed, so tracking never blocks a pick.
- `getCurated(l1Slug): UnsplashPick[]` is read from the constants. It returns `[]` for an unknown slug.

**Request budget (owner, 26 Oct): the site never reaches Unsplash's 50/h limit.** All in the service, in-memory per app process, no new table. Numbers live in `lib/constants/index.ts` as `UNSPLASH_LIMITS`.
- **Cache.** Search results are cached by `lang|normalised query|page` (trim, lower-case, collapse spaces) for 24 h, LRU of 200 entries. A cache hit makes no request and spends no budget.
- **Per-process budget.** At most 12 outgoing requests per rolling hour per process (3 processes per colour → 36 < 50). Searches may use only the first 10; the last 2 are kept for `trackDownload`, so attribution keeps working when search is spent.
- **Unsplash's own count wins.** Every response's `X-Ratelimit-Remaining` is remembered with its time; while the last seen value is ≤ 8 (other processes, the curated script, a local dev box share the key), new searches are refused until that hour has passed. `trackDownload` still runs above 2.
- **Per user.** At most 6 searches per user per 10 minutes (cache hits do not count). Over it → `ActionError('SEARCH_RATE_LIMITED')`.
- **Spent budget** → `ActionError('SEARCH_UNAVAILABLE')`. The picker then shows a short "Meklēšana šobrīd nav pieejama, izvēlies no piedāvātajiem" line in place of results and keeps the curated photos; `SEARCH_RATE_LIMITED` shows "Pārāk daudz meklējumu, mēģini pēc dažām minūtēm". Both keys go in `messages/*` under `errors.*`.
- **No page past what exists**: "Vairāk" shows only while `hasMore`, max page 3 per query.
- **Pings deduplicated**: `trackDownload` sends at most one ping per photo id per process per hour.
- Unit of truth for the reviewer: one search click with a cold cache costs exactly 1 request; the same query again costs 0.

**`actions/unsplash-actions.ts` (new, ≤ 60 lines)**
- `searchUnsplash(input)` requires a session (`UNAUTHORIZED`), parses with `unsplashSearchSchema` (`VALIDATION_FAILED`), calls the service, and returns `ActionResponse<{ photos; hasMore }>`.
- `trackUnsplashPick(photoId)` requires a session, parses the id, calls `trackDownload`, and always succeeds once the input is valid. Curated picks call it too, since their entries carry the photo `id`.
- `types/actions.ts`: add `'SEARCH_UNAVAILABLE'`, `'SEARCH_RATE_LIMITED'` and `'BANNER_URL_NOT_ALLOWED'` to `ERROR_CODES`.

**Services write the credit.** In `group.service.ts` (create ~432, update ~641) and `event.service.ts` (create ~471, update ~575), call `assertBannerAllowed` with the stored value and the caller's site-admin flag. The action passes `isSiteAdmin(session)` from `@/lib/site-role` as a typed option, so the service does not read the session. Then write `bannerCreditName`/`bannerCreditUser` from `bannerCredit` when the URL is an Unsplash URL, and `null` otherwise (invariant 4).

**Services read the credit.** These add `bannerCredit: { name; username } | null`:
- `GroupService` context type (line 82) and its mapper (~290)
- `event-page.ts` (`imageCredit` next to `image`, line 101)
- `event-panel.ts` (select both columns on the event and the group; the credit falls back the same way the image does, line 93)
- `useGroupSettingsForm` and `useEventForm` defaults, plus the event edit page's `EventToEdit`

Cards (`group-card.ts`) are unchanged.

**Env.** `.env.example` gets a commented block: `# Unsplash (banner search; optional, curated photos work without it)` and `UNSPLASH_ACCESS_KEY=`.

## 10. Risks

- **The curated list depends on the key and a guessed query.** If few draft paths match, the script's top results fill in, and their subjects can be off. The owner review in the picker is the gate, not the builder's judgement.
- **Unsplash production approval** asks to see attribution and download tracking working. Both are acceptance items. The demo limit (50/h, shared across the site) is why search is submit-only and 8 per page.
- **Permission regression.** Today any group admin can paste any URL. After R26-1 only Unsplash URLs, unchanged values or a site admin can save one. Check the admin categorisation form (`AdminGroupCategorizationForm.tsx:57` sends `bannerImage: ''`) still saves (`''` is allowed).
- **Wizard trigger lists.** If `'bannerImage'` stays in the step-0 trigger after the field moves, a bad value blocks step 0 with no field shown.
- **A stale credit** if a form sends a new URL with the old credit. `BannerPicker.onChange` always sets both together, and the service clears the credit for non-Unsplash URLs.
- **Hotlinked image disappears** (photographer deletes it). The picture shows broken. Out of scope; a later fix could fall back to `PictureFallback` `onError`.

Uploading images, storing photo ids, credits on cards and rows, profile avatars, an `onError` fallback, changing seed or demo banners.
