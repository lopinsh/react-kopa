# R23 spec · The admin tool panel

Spec for release R23 (drawing for intent: `docs/development/r23-admin-drawer.html`; an illustration at 375 and 1280 px, not a pixel spec). Written 24 Oct 2026 against `main` at `0b15450`. Owner approved the split below on 24 Oct.

**Sessions**

| Session | What | Builder budget |
|---|---|---|
| **R23-1** | The panel: one admin panel replaces the feedback and translate pills and modes. Float, drag, dock (from 768), bottom sheet (phones). Tabs Atsauksmes and Tulkot carry today's content. Shield menu: one toggle. | <= 60 tool calls |
| **R23-2** | The Dizains tab: click a text, edit its type role in the draft theme, see it server-rendered. | <= 60 tool calls |

R23-1 builders read §0 to §9 plus Invariants, Acceptance, Risks, Owner questions. R23-2 builders read §10 to §14 plus the same shared sections; §2 (the panel frame) is the API they plug into.

## Invariants (the reviewer checks each)

1. **Non-admins see nothing new.** Signed out, signed-in member, or anyone setting the cookie by hand: the HTML, the messages payload and the JS chunks are as today (the panel is a `dynamic(..., { ssr: false })` chunk mounted only when the server says so). Public visual baselines: **0 px diff, no PNG updated.** No admin screen is added to `tests/visual/`.
2. **Server decides the mode.** Which tab is open lives in one httpOnly cookie checked against `isSiteAdmin` on the server, like today's `lib/feedback/server.ts`. Translate markers (`i18n/request.ts`) appear only on the Tulkot tab.
3. **No DB change.** No migration. New service reads only (`groupBy`, `findMany`).
4. **Laws.** Prisma only in `lib/services/`; actions return `ActionResponse<T>` with uppercase codes and start with `requireSiteAdmin()`; Zod as a value only in `lib/validations/`; no `any`; constants in `lib/constants/`; every mutation has an `isPending` guard. **Taxonomy Law:** the page accent and the type variables keep coming from the layout's server `<style>`; the panel never writes a theme or type variable on the client (R23-2).
5. **Existing behaviour carries over:** feedback pins, named-element picker, "Komentēt jebkur", the note dialog and note card, the translation editor's suggest/approve flow, `?part=type` Burti page, the ThemePreviewBar when the panel is closed.
6. The panel is a tool, not a pop-up: no scrim, no scroll lock, no focus trap, a click on the page never closes it (behaviour.md "Pop-ups" does not apply; §2.6 says what does).

## 0. Motivation and design alignment (R23-1)

Today two pills (`components/feedback/FeedbackMode.tsx:108`, `components/translate/TranslateMode.tsx:52`) float in different corners at `z-[60]`, each with its own toggle in the shield menu (`components/shell/AdminMenu.tsx`) and its own cookie. They overlap the bottom nav and slide-overs, and there is no room for a third tool. One panel with tabs gives one place, one toggle, one Escape story. Service, Action and Context Laws hold because the panel reuses the existing actions and providers (`FeedbackModeContext`, the translate context in `Providers`); the new code is UI plus two read-only service methods.

### 2.1 Look

Built from the Design chapter (`docs/handbook/design.md` Foundations: Type, Shape, Space and depth, Motion and icons), not from the drawing's CSS. One box: `bg-surface shadow-premium frame rounded-2xl` floating; docked: full height on the right, `line` on its left edge only, no radius. Width `w-88` floating and docked (cap `max-w-[calc(100vw-1rem)]` is a width, not spacing; if `ui:check` flags it use `ui-allow: panel cap`). Top bar `min-h-11`, title `text-item`, the hint line under the tabs `text-meta text-foreground-muted` (drawing `#sub`). Tabs are plain tabs (design.md Components: tabs stay plain), the selected one carries `aria-selected` plus an underline in `--primary`. Icon buttons `IconButton size="md"` with `aria-label`. The body scrolls (`overflow-y-auto`), the footer sticks. Mark the root `data-feedback-ignore data-translate-ignore data-admin-panel`.

### 2.2 Floating and drag (from 768)

- Default place: top 80 px, right 24 px, floating (drawing `st`, source `r23-admin-drawer.html` `place()`).
- Drag by the top bar: `pointerdown` on the bar (ignore when the target is a `button`), `setPointerCapture`, `pointermove` updates x/y, `pointerup`/`pointercancel` ends. The bar has `touch-none` (`touch-action: none`) so a tablet drag does not scroll; `select-none` while dragging (a `data-dragging` attribute on the root, no transition while it is set).
- Clamp to the viewport (8 px margin) on every move and on `resize`; a stored place from a bigger screen is clamped on load.
- Position is written as CSS variables on the panel root (`style={{ '--panel-x': ..., '--panel-y': ... }}`, read by `left-[var(--panel-x)] top-[var(--panel-y)]`), the same pattern as the hover boxes in `FeedbackMode.tsx:100`. This is a tool overlay, not page theming.
- **Dock:** release with the pointer within 40 px of the right edge docks; while within it, show an edge hint (a `bg-primary/20` strip on the right, `aria-hidden`). The ⇥ button docks, ⇤ undocks (`aria-label` dock/undock, `aria-pressed` not used: the label changes). Dragging the docked top bar pulls it loose: it becomes floating under the pointer (offset 170/20 px as in the drawing) and follows.
- Persist `{ x, y, docked }` in localStorage on pointerup and on dock toggle, never on every move.
- Keyboard users move it with ⇥/⇤ only; no keyboard drag (default).

### 2.3 Docked drawer and the page aside

- Docked: `fixed inset-y-0 right-0`, full height, `w-88`.
- **768 to 1279:** it overlays the page (the page keeps its width).
- **>= 1280:** the page moves aside. The panel sets `document.documentElement.dataset.adminDock = ''` while docked and removes it on undock/unmount. `app/globals.css` gets one rule: `@media (min-width: 80rem) { html[data-admin-dock] [data-shell] { padding-right: 22rem } }` with `data-shell` added to the shell `div` at `layout.tsx` (`flex h-dvh flex-col`). Header and the scroll container shrink together; bars still span what is left (AGENTS.md Fluid). The slide-over panel (`@panel`) and `Overlay` are fixed to the viewport and stay centred on it (default; they sit under the drawer's z, §2.5).
- On reload the docked state is read from localStorage after mount, so the page shifts once for an admin on load. Accepted (admin only; Risks).

### 2.4 Phone bottom sheet (< 768)

- One sheet above the bottom nav: `fixed inset-x-0 bottom-[calc(4rem+var(--cookie-banner-h,0px))]` (same offset as the scroll container in `layout.tsx`), `rounded-t-2xl`, no drag by the top bar, no ⇥.
- Heights: **bar** (handle + tab row + top bar, about 100 px), **half** (50 dvh), **full** (92 dvh minus the nav). Default on first open: half.
- The handle (`components/admin-panel/PanelTopBar.tsx`, a `button` with `aria-label` "Mainīt paneļa augstumu", `touch-none`, a 44 px tall hit area holding a short `rounded-pill bg-border` grip): tap toggles bar ↔ half; drag follows the finger (height as a CSS variable) and snaps to the nearest of bar/half/full on release (drawing `#grab` handler). Keyboard: Enter/Space = tap; ArrowUp/ArrowDown step through bar → half → full.
- While the sheet is open, the scroll container gets bottom room so the last content can be scrolled above it: the panel sets `--admin-sheet-h` on `<html>`; `globals.css` `@media (max-width: 47.99rem) { html[data-admin-sheet] #main-content { padding-bottom: calc(4rem + var(--cookie-banner-h,0px) + var(--admin-sheet-h)) } }`.
- Persist the height in localStorage.

### 2.5 Layers (z)

Today: bottom nav `z-40`, `Overlay` (slide-overs, dialogs, sheets) `z-50`, header and menus `z-50`, element picker box `z-[54]`, pins `z-[55]`, search overlay and DiscardGuard `z-[60]`, feedback dialog, note card, translation editor `z-[70]`, toasts `z-[100]`.

The panel is **`z-[58]`**: above slide-overs (an admin annotates or translates inside a slide-over), the bottom nav and the pins; below the search overlay, DiscardGuard, and the feedback/translate dialogs it opens. Add the value to a short comment in `AdminPanel.tsx` listing this ladder.

Focus trap: `hooks/useFocusTrap.ts` handles Tab inside an open `Overlay`. Make it skip when `document.activeElement` is inside `[data-admin-panel]` (one `closest` check), so Tab inside the panel is not pulled back into the slide-over. Clicks in the panel do not reach the Overlay scrim (the panel is a sibling above it), so the slide-over stays open.

### 2.6 Focus and Escape

- Opening (from the shield item): focus goes to the selected tab. Closing (✕, Escape, shield item): focus returns to the shield trigger if it is in the DOM (`[data-ui=<UI.shieldMenu trigger>]` or the element focused before opening, kept in a ref), else to `#content`.
- Escape is handled by a `keydown` listener **on the panel root** with `stopPropagation`, so it never also closes a slide-over: 1) focus in an `input/textarea/select` inside the panel: blur it and focus the selected tab; 2) a selection in the tab (Tulkot: selected key; Dizains: selected role): clear it; 3) else close the panel (`setAdminPanel(null)`).
- Escape with focus outside the panel belongs to the page (slide-overs, menus). Remove the window Escape handler in `FeedbackMode.tsx:58-70` that turned the mode off; keep its "close the open note/dialog first" part inside the dialogs as today.
- Tabs: ArrowLeft/ArrowRight move and select (drawing `#tabs` keydown), Home/End to first/last. Each tab panel `role="tabpanel"` with `aria-labelledby`.
- The panel root is `role="region"` with `aria-label` "Administratora rīki".

### 2.7 Pauze

The top bar's Pauze button (`aria-pressed`, label changes to "Pauzē: klikšķi strādā") is shown on Atsauksmes and Dizains, hidden on Tulkot (drawing `setMode`). It lives in `AdminPanel` state and is passed to the tab; on Atsauksmes it replaces today's `paused` state in `FeedbackMode.tsx:35`.

### 2.8 Reduced motion

Dock/undock and sheet snaps animate `transform`/`height` with `motion-safe:transition-[transform,height] duration-slow ease-standard` (name the properties; design.md Motion). No transition while `data-dragging`. The R23-2 scroll-to-element uses `behavior: 'smooth'` only when `matchMedia('(prefers-reduced-motion: no-preference)')` matches. The edge hint and highlight are colour changes, never motion alone.

## 10. Goal and structure (R23-2)

The Dizains tab lets an admin click any text on any page, see which type role it uses, and change that role (font, size per phone/desktop, weight, reset) in the draft theme, with the change rendered by the server on every page they visit until they publish or discard. It is the R22-2 role editor (`components/admin/design/TypeRoleEditor.tsx`, whose header comment already reserves it for this drawer) placed next to the live page.

Tab structure (top to bottom): hint line; **Loma** `Select` (all `TYPE_ROLES`, names from `admin.design.type.roles.*`, placeholder "Izvēlies vai noklikšķini lapā…"); with no role: "Noklikšķini uz teksta lapā vai izvēlies lomu."; with a role: role name (`text-item`), "Kad lietot." + `admin.design.type.roleHints.<id>`, "Šajā lapā: {count} vietās", the variant line when clicked on a variant (§11), then `TypeRoleEditor`, then "Mainās visur, kur lieto šo lomu. Redzi tikai tu, līdz publicē."; bottom link "Visi burti un sistēma →" to `/admin/design?part=type`. Footer: changes count, **Publicēt** (`publishPreviewTheme`), **Atmest** (`discardPreviewTheme`). Pauze in the top bar (§2.7).

## 11. Picking a text (R23-2)

## 12. Saving into the draft (R23-2)

- **Initial value:** the layout passes `designTheme` (the `ThemeInput` fields of `getActiveTheme()`: `presetKey, light, dark, headingFont, bodyFont, styleKey, type`, as `app/[locale]/admin/design/page.tsx:43` builds it) to `AdminPanelLoader` only on the Dizains tab.
- **Edit:** `TypeRoleEditor`'s `onType(type)` builds `{ ...designTheme, type }`, stores it in tab state (the stepper shows the new value at once) and schedules a save: debounce 400 ms, one save in flight at a time (`isPending` guard; if a newer value arrives while saving, save once more after), via the existing `savePreviewTheme` (sets the preview cookie, `revalidatePath('/', 'layout')`), then `router.refresh()`. The page's type changes when the server's `<style>` arrives: no client-side CSS variables (Taxonomy Law; Invariant 4).
- **Refresh vs local state:** the panel stays mounted across refresh and client navigation (it lives in the locale layout). It takes the server's `designTheme` again only when no save is pending, so a refresh never undoes a step mid-edit. Key nothing on the theme id (a new draft row gets a new id on every save, `theme.service.ts:99-102`) so the panel does not remount.
- **Errors:** `CONTRAST_TOO_LOW` cannot come from a type change but can from an existing broken draft; show the `errors.*` toast and keep the local value.
- **Survives page moves:** the draft lives in the DB and the cookie; a client navigation keeps the panel and its selected role; a reload keeps the draft (selected role is lost; fine).
- **Footer:** "Nav izmaiņu" / "{count} izmaiņas melnrakstā" counts saves since the tab opened (session state). Publicēt: if the resolved `item` desktop size is >= `title` desktop size (`resolveTypeRoles`, `lib/theme/type-edit.ts:35`), a `ConfirmDialog` (or the existing confirm component in `components/ui/`) warns "Nosaukums ir lielāks par lapas virsrakstu. Publicēt tik un tā?"; otherwise publish at once. Both buttons with `isPending` guards, then `router.refresh()`.

## Risks

- **Translate markers and the panel's own text:** the panel lives under `data-translate-ignore`, but its `admin.panel` strings are also marked while Tulkot is on. `useMarkedText` already ignores `[data-translate-ignore]`; check that `markedKeysOnPage` does too, so panel keys are not listed as "on this page".
- **Capture-phase clicks (R23-2)** may block a control the admin needs (the header search, the shield itself). The picker only acts when a role text is found and never inside `[data-admin-panel]`; the header's role texts are pickable by design; Pauze is the way out. Test the shield trigger (an icon, no role) still opens.
- **Refresh churn (R23-2):** each saved step re-renders the layout and creates a new draft row (`saveDraft` deletes and recreates). The debounce limits it; watch for focus loss in the stepper after `router.refresh()` (the panel must not remount).
- **Dock shift on load:** the docked state is client-only, so a docked admin sees the page jump once per hard load at >= 1280. Accepted by the localStorage default; a cookie would remove it (not taken: owner chose localStorage).
- **Overlay focus trap / Escape:** the `useFocusTrap` exception must not let Tab escape a dialog into the page; only `[data-admin-panel]` is exempt.
- **Size of R23-1:** five commits and the most files; if the builder passes 50 calls before commit 4, stop after commit 3 and report (Tulkot then moves to its own short session, with the old translate pill kept working until it lands).
