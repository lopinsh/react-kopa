# R30 Aktivitāte

## Goal

Site admins see what happens on the site, newest first: who signed up, which groups and events were made, who joined, who signed up for events, which announcements went out. The feed is read from timestamps that already exist; nothing new is recorded.

## Invariants

- No schema change, no migration, no new write anywhere. Only reads.
- Service Law: all Prisma reads in `lib/services/activity.service.ts`; the page and action never touch Prisma.
- Admin only: page `requireAdminPage(locale, '/admin/activity')`, action `requireSiteAdmin()`. Every site admin sees it (not owner only).
- Event titles come from `resolveEventText` (`lib/translations.ts:141`) in the viewer's locale; group names are `Group.name` (groups have no translations). Never build a title from a slug.
- Dates through `useDateFormatter` / `createDateFormatter` (`lib/date-format.ts`), never `toLocale*`.
- None of the 12 visual baselines changes (no public screen is touched).

## Sources (R30-1)

Each source is one `findMany` with `orderBy: [{ <at>: 'desc' }, { id: 'desc' }]`, `take: PAGE + 1`, and the cursor clause below. Kinds have a fixed rank (order of this table) for ties.

| Kind | Chip | Model, time field | Actor | Target | Notes |
|---|---|---|---|---|---|
| `USER_JOINED` | users | `User.createdAt` | the user | none | |
| `GROUP_CREATED` | groups | `Group.createdAt` | current OWNER membership's user | group page | the original creator isn't stored; the current owner stands in |
| `MEMBER_JOINED` | membership | `Membership.joinedAt`, role MEMBER or ADMIN | the member | group page | approval doesn't move `joinedAt`, so for request groups the time is the request time |
| `MEMBER_REQUESTED` | membership | `Membership.joinedAt`, role PENDING | the person | group page | OWNER rows are skipped (the group creation covers them) |
| `EVENT_CREATED` | events | `Event.createdAt` | `Event.creator` (nullable: "unknown") | event page | |
| `EVENT_SIGNUP` | events | `Attendance.joinedAt`, status GOING, PENDING or WAITLISTED | the person | event page | `joinedAt` is reset on status change (`event.service.ts:773`), so the row shows the latest status at its latest time; DECLINED skipped |
| `POST_PUBLISHED` | posts | `Post.createdAt` | `Post.author` | group's announcements page, label = post title or group name | archived posts still show |

Deleted groups and users cascade away with their rows, so they simply drop out of the feed. A hidden group (`hiddenAt` set) shows with a "paslēpta" marker after its name, on every row that targets it (group, its events, memberships, posts).

Links (locale-less, `Link` from `@/i18n/routing`):
- group: `/${TaxonomyResolver.resolve(group.category).l1Slug}/group/${group.slug}` (same as `moderation.service.ts:184`, so select the category chain the resolver needs)
- event: the group path + `/events/${event.slug}`
- announcements: the group path + `/announcements`
- user: `/profile/${username}` when `username` is set, else plain text name. Name fallback: `name ?? username ?? t('unknownUser')`.

## Cursor and paging (R30-1)

Page size `ACTIVITY_PAGE_SIZE = 50`. Rows sort by `(at desc, kindRank asc, id desc)`. The cursor is the last shown row, encoded as `${at.toISOString()}~${kind}~${id}` (validated by Zod). Many seed rows share one `now()` timestamp, so a plain `at < before` would lose rows at a page edge; per source, with cursor `(t, r, i)` and the source's rank `k`:
- `k > r`: `at <= t`
- `k == r`: `at < t` OR (`at == t` AND `id < i`)
- `k < r`: `at < t`

Merge all queried sources, sort, keep the first 50; `nextCursor` is set when more than 50 came back in total. With a type filter only that chip's sources are queried.

## Risks

- **Timestamps aren't events.** Membership time is the request time for request groups; attendance time moves with each status change; group "creator" is today's owner. The row wording is honest enough for an admin glance; a true log needs writes (later release if wanted).
- **Unindexed sorts.** Four sources sort on columns without an index. Fine now; if the page gets slow, a later release adds indexes (additive migration).
- **Privacy.** The feed shows private-profile users and members-only announcements' titles to admins; that's within admin reach already (`requireAdminPage`), so no extra filtering.
