## Goal

A person can leave one free-text way to reach them (phone, email, Telegram, a link). By default only people who share a group with them see it; a switch opens it to everyone signed in. Nobody signed out ever sees it, and the value never leaves the server for a viewer who may not see it.

## Invariants

- **Server-side only.** Who sees the contact is decided in services (`lib/services/contact.ts`, used by `UserService.getProfileView` and `GroupMembersService.getMembersPage`). A viewer who may not see it gets `contact: null` in the context; the raw value is never in the HTML or the RSC payload for them. No client-side hiding, no `contactVisibleToAll` sent to other viewers.
- **"Share a group"** = both have a membership with `role` not `PENDING` (OWNER, ADMIN, MEMBER; there is no status enum, PENDING is a role, `schema.prisma:471`) in the same group with `hiddenAt: null`. Same definition as the profile's shared groups (`user.service.ts:208`).
- **Private profile wins.** `isProfilePublic = false`: the contact goes to nobody but the person themself (others already get the private empty state, `user.service.ts:187`; member rows get `contact: null` too). Site admins included (see Owner questions 1).
- **Signed out never.** `viewerId` undefined always gives `null`, whatever the switch says.
- Additive migration only (expand); the old app ignores the two columns.
- Plain text render; a link only when the whole value is one email, phone number or http(s) URL (below). Never `dangerouslySetInnerHTML`.
- No visual baseline changes (the seed sets no contact; see Visual baseline).

## Visibility rule (R32-1)

`contactFor(person, viewer, ctx)` returns the string or `null`, checks in this order (first match wins):

| # | Case | Result |
|---|---|---|
| 1 | `person.contact` empty | `null` |
| 2 | viewer is the person (not the `asStranger` view) | contact |
| 3 | `person.isProfilePublic = false` | `null` |
| 4 | no viewer (signed out) | `null` |
| 5 | `person.contactVisibleToAll` | contact |
| 6 | viewer is a site admin (`isSiteAdmin(role)`, `lib/site-role.ts`; ADMIN and OWNER) | contact |
| 7 | they share a group (definition above) | contact |
| 8 | otherwise (stranger, or only PENDING in a shared group) | `null` |

- Mans profils (`asStranger: true`, `app/[locale]/(me)/profile/page.tsx:26`) is "a signed-in person who shares no group": skip row 2, so it shows the contact only when `contactVisibleToAll` (rows 5/8). The `withoutGroups` call in `(me)/layout.tsx:23` returns `contact: null` (it only needs the head).
- Row 6 needs the viewer's role: one lazy `user.findUnique({ select: { role: true } })` only when rows 1 to 5 didn't decide. Row 7 is one `membership.findFirst` (`userId: person.id, role: { not: 'PENDING' }, group: { hiddenAt: null, members: { some: { userId: viewerId, role: { not: 'PENDING' } } } } }`, `select: { id: true }`). Profile pages are per person, so two small queries at most.
- Member rows (Biedri) decide per row without queries: the page already requires `group.user.isMember` (non-PENDING, `group.service.ts:255`, members page line 47), so for an accepted row in a non-hidden group row 7 is true. Rule per row: self → contact; `!isProfilePublic` → null; `!group.moderation.hidden` or `contactVisibleToAll` or `group.moderation.isSiteAdmin` → contact; else null. Request rows (`RequestRowData`, PENDING applicants) get no contact field at all.

## Risks

- **Leak by a forgotten path.** Any new `user` select that spreads the row into a context would carry `contact`. Mitigation: `PROFILE_USER_SELECT` stays internal; reviewer greps for `contact` in `lib/services` and the context types.
- **Shared-group by hidden group.** A moderation-hidden group stops counting at once; members lose the contact without notice. Intended (a hidden group isn't a place to meet).
- **Abuse.** Free text could carry spam links. They are `nofollow ugc`, need a shared group by default, and the profile can be reported as today. No moderation queue for contacts.
- **Admin reach.** Site admins see contacts of public profiles without sharing a group (row 6); the privacy page says so.
