## 0. Motivation and design alignment

- **One level across, one down (AR-21).** Today's `AdminNav` is five dropdown groups with hover logic, a phone menu and a page heading per page: two look-alike layers. The new frame makes the structure visible: five sections never move; the pages of the current section are always listed; nothing opens on hover.
- **Context Law for frames (build plan section 6).** The layout fetches counts through `AdminService` and hands them to a small client provider; client parts read them with a hook (`useAdminFrame()`), never prop-drilled; the current section/page is derived from `usePathname()` plus the one data file.
- **Defensive and Action laws** are untouched (no actions edited). The `confirm()` replacements follow Defensive Coding: every confirm has `isPending`.
- **Small components.** `AdminNav` (280) is replaced by three files under 150 lines each; `SlideoverL1View` (297) is split when the categories page is restyled.
- **Reuse.** `Overlay`/drawer pieces from R3a/R8; `Badge`-like pills exist in the own-area frame (grep before writing a new one); `ConfirmDialog` for things that cannot be undone, `ConfirmPopover` for undoable ones (components/ui).

## 1. The one data file and the frame provider (R11-1, commit 1)

- **`lib/constants/adminNav.ts`** (Constants Law): one typed list, in menu order.

```ts
type AdminNavItem = { id: string; href: string; match: 'exact' | 'prefix'; icon: LucideIcon; badge?: 'tags'|'cities'|'reports'|'suggestions'; ownerOnly?: true; parts?: { id: string; href: string }[] };
type AdminNavSection = { id: 'moderation'|'structure'|'site'|'team'|'development'; items: AdminNavItem[] };
```

  Items by section (ids become `admin.nav.*` keys): moderation `overview` (`/admin`, exact), `reports`; structure `categories`, `locations`; site `design` (parts `colors`, `categoryColors`, `fonts` as `?part=`; check the part ids in `DesignPartTabs`), `translations`; team `team`; development `feedback`, `handbook` (prefix; its chapters are **dynamic**, see section 3), `buildPlan`, `redesign`.
  - `match: 'exact'` only for `/admin`; the categorization page (`/admin/groups/...`) belongs to section `structure` with no page marked: the resolver returns `{ section, item: null }` for it. Icons: reuse the ones in today's `AdminNav` (`AlertTriangle`, `EyeOff`, `Network`, `MapPin`, `Languages`, `Palette`, `UserCog`, `MessageSquareText`, `BookOpen`, `ListChecks`, `Brush`); `lucide-react` only.
  - A pure `resolveAdminLocation(pathname, tab?)` and `visibleSections(isOwner)` live next to the list (`lib/admin-nav.ts`, no React) so they are testable by eye and shared by the three components.
- **`AdminFrameProvider`** (`components/admin/frame/AdminFrameProvider.tsx`, client): holds `counts`, `isOwner`; `useAdminFrame()`. The layout (`admin/layout.tsx`) keeps its current role check and counts fetch, passes `isOwner` from `isSiteOwner(session.user.role)` (already imported there via `site-role`), and wraps `children` in the provider when admin.
- **Handbook chapters** reach the frame from the server: the layout cannot know the open chapter, so the chapter list for the Rokasgrāmata parent comes from `HandbookService`/the existing loader that `handbook/[chapter]/page.tsx` uses (grep `chapters` there). The layout loads the chapter list **once** (titles + slugs, no headings) and puts it in the provider; `HandbookShell` then renders only the on-page heading list (its `headings`) as a compact "On this page" list inside the article column (sticky on `lg`), not the chapter list. Default: the chapter list does **not** collapse; Rokasgrāmata's chapters are indented parts of the left list, the "UI elementi" entry last among them.

## 2. The frame (R11-1 and R11-2, commits 1–2)

Replaces `components/admin/AdminNav.tsx`; new files `components/admin/frame/{AdminSections,AdminPagesNav,AdminDrawer,AdminFrame}.tsx` (+ the provider). Each ≤ 150 lines.

- **`AdminFrame`** (server-friendly wrapper, composed in `admin/layout.tsx`): under the site header it renders `AdminSections` (full-width bar, `sticky` under the header, same offset the own-area section menu uses after `3d1165c`: "section menu sticky and marking in the shell's scroller"; read that fix before choosing the scroller), then a container (`container mx-auto px-4`, content max width per the page) with a two-column grid at `lg`: `AdminPagesNav` (side column, fixed side-column width, the one fixed width allowed) and the page. A section with **one page** (Komanda) renders no left column; the page uses the full container width. Below `lg` the left column is gone: a bar with ☰, the page title and the part as small text (as `rd-gbar`), opening `AdminDrawer`.
- **`AdminSections`**: five links (plain links, `aria-current="page"` on the open section), icon optional, label from `admin.nav.sections.*`, red/primary badge pill with the section's summed count. Horizontally scrollable on phones is **not** used: below `sm` the bar is hidden (the drawer carries the sections); from `sm` it shows all five (they fit at 640 px in LV; the reviewer checks 640 and 768). Opening a section goes to its first visible item.
- **`AdminPagesNav`** (`nav aria-label` = `admin.nav.pagesLabel`): the open section's pages as a vertical list; the open page marked (`aria-current`) with the tint of the drawing; a page with parts shows them indented under it **when it is the open page** (Dizains parts via `?part=`, Rokasgrāmata chapters). No heading repeats the chosen item: the list has no title; the page title is the page's own `<h1>`.
- **`AdminDrawer`** (phones and `< lg`): headed by the shield icon and "Administrēšana"; all five sections as rows (open one expanded with its pages and parts, others collapsed, badge pills); built on the same `Overlay` + `useBackClose` as the other drawers (focus trap, Esc, Back closes, scrim). Opens from the ☰ in the bar; closes on navigation.
- **Pages' own headings.** Each page keeps one `<h1>`; the descriptive subtitle (`admin.nav.desc.*`) may stay under it; pages drop their own outer `container … py-8 max-w-6xl` wrapper where the frame now supplies the container (check each page: `admin/page.tsx` 46, `team/page.tsx` 26, `HandbookShell` 77).
- **Keyboard:** all links are in tab order; no menu roles, no arrow-key menu logic (it was a menu; this is navigation). The drawer has the dialog behaviour of `Overlay`.
- **Deleted with `AdminNav`:** hover timers, `useClickOutside` use, the `PHONE` menu, unused `admin.nav.desc.*` and `admin.nav.groups.*` keys are renamed (section 7), not left orphaned.

## 11. Risks

- **Many pages, little logic.** A page keeps an old outer container and ends up double-padded or too narrow under the frame: the reviewer opens all thirteen URLs at 360 and 1440.
- **Sticky offsets.** Sections bar under a sticky site header, plus the Dizains preview bar, plus the page's own sticky bars: three sticky layers can stack and hide content. Read how the own-area frame solved it (`3d1165c`), give the preview bar `top` = header + sections bar, and check scrolling to an anchor.
- **Handbook chapters in the layout.** An extra read per admin request; keep it to titles from the existing loader (cached markdown listing), and make sure it runs only for admins.
- **Dizains part navigation.** Today parts switch with `history.replaceState`; links navigate and may remount `DesignEditor` and lose an unpublished preview. Use `scroll={false}` links, keep editor state above the part switch (it already holds all parts), and test preview, switch part, publish.
- **Destructive dialogs on removed rows.** After a delete the trigger button is gone: pass `returnFocusRef` to the list heading or the next row.
- **Redesign page embed** may rely on the old full-width layout; check at 1920.
