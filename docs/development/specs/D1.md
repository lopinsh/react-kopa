# D1 spec · Demo content

Owner-approved plan, 26 Oct 2026. Docs only until built. No schema change, no UI change, no i18n keys, no visual baseline change.

## 0. Goal and why

The live site looks empty: a visitor opening a theme finds nothing to join and cannot tell what a group could be. D1 fills every active sub-theme (L2) with at least one clearly imaginary demo group (~55 in all), each with an About text that says it is a demo and invites the reader to create a similar real one, a second section, 2-3 upcoming events and 2 announcements. It is a separate script, `prisma/demo.ts` (`npm run db:demo`), run on the server by a manual workflow, re-run monthly to move event dates forward. It adds 20 L2s to the live taxonomy first.

### Motivation & Design Alignment

- **Separate from `prisma/seed.ts`**: the seed feeds CI smoke and the visual baselines (zero-pixel tolerance, AGENTS.md "Visual baseline"); touching it would redraw every board screenshot. The seed also wipes all groups (seed.ts:201-206), so it must never run on production; the demo script only ever writes rows it owns.
- **Service Law**: `prisma/**` is outside the eslint Service Law scope (eslint.config line 30), like the seed. The script uses Prisma directly; it never imports app code (see Invariant 6).
- **Taxonomy Law**: demo groups are stored like wizard groups (`Group.categoryId` = L1, the L2 as a `tags` connection, group.service.ts `createGroup`), so the accent and the board counts come out right without app changes.
- **Constants Law** does not apply: the demo content is data, kept in `prisma/demo-data/`, separate from the logic in `prisma/demo.ts` (owner's ask).
- **Text in several languages** (handbook behaviour.md "Text in several languages"): About, the second section and events carry `lv` (original) and `en`; announcements are one language (`lv`), like real ones. Nothing is machine-translated at runtime; the builder writes both texts.
- **Honesty** (handbook values/voice): every demo group says so in its first words, and so does its card tagline (the tagline is the excerpt of the order-0 section, group-card.ts:75-83).

## Invariants (reviewer checks each)

1. `prisma/seed.ts`, `tests/visual/**`, `.github/workflows/ci.yml`, `prisma/schema.prisma` and `prisma/migrations/**` are unchanged. No visual baseline changes; no screen is listed for this release.
2. **Demo identity**: a demo user is a `User` whose email ends in `@demo.ejam.invalid` (`.invalid` is a reserved TLD: no mail can ever arrive, no one can sign in by email link). A demo group is a group whose OWNER membership belongs to a demo user. Nothing else is "demo".
3. **Never touches non-demo rows**: the script writes, updates or deletes only demo users, demo groups and rows inside demo groups that a demo user owns (their memberships, demo-authored posts, the group's sections and events). Real users' memberships, attendances and posts in a demo group are left alone. The only non-demo writes are the 20 L2 upserts with `update: {}`.
4. **Idempotent**: a second run with the same data gives the same row counts; it updates demo group fields and texts and moves event dates; it does not duplicate anything.
5. **Taxonomy is read live**: L1 and L2 ids come from the DB by slug; the 20 new L2s are upserted with `update: {}` (an admin's later edit, rename or rejection of one is kept). A data entry whose L2 is missing or not `ACTIVE` is skipped with a warning, never created.
6. **Self-contained under `prisma/`**: `prisma/demo.ts` imports only `@prisma/client` and `./demo-data/*`. No `@/` path imports (plain `tsc` leaves them unresolved in the container) and no relative imports outside `prisma/` (the runner image copies only `/app/prisma`, Dockerfile runner `COPY ... /app/prisma ./prisma`). Copy `slugify` from seed.ts:128-136.
7. Zero-Any Law holds (`prisma/**` still runs through `npm run typecheck`); no `any`, typed data via `prisma/demo-data/types.ts`.
8. Demo users: no `password`, `role: USER`, `allowDirectMessages: false`, `isProfilePublic: true`, `showGroupsOnProfile: true`.

## 1. Script `prisma/demo.ts` (D1-1)

Order of work, each step logged with one line:

1. **Taxonomy.** Upsert the 20 L2s of `prisma/demo-data/taxonomy.ts` by `slug` (create: `level: 2`, `parentId` = live L1 by slug, `status: ACTIVE`, `slugLv: slugify(lv)`, `titles` lv + en; `update: {}`). L1 missing → warn, skip its L2s.
2. **Cities.** Read `City` where `status: ACTIVE` once; a data city not in it falls back to `Riga` with a warning. Data uses the slugs from migration `20261012110000_create_city_table` (`Riga`, `Jurmala`, `Liepaja`, `Daugavpils`, `Valmiera`, `Cesis`, `Sigulda`, …).
3. **Users.** Upsert the 15 demo users by email (`update` sets name, username, bio, avatarSeed, cities, the Invariant 8 flags).
4. **Groups.** For each data entry, in a transaction per group:
   - Resolve L2 by slug (Invariant 5), L1 = its parent.
   - Find the group by `(categoryId = L1, slug)` (unique, schema `@@unique([categoryId, slug])`). Exists and owned by a demo user → update. Exists and not demo → skip with a warning (slug taken by a real group). Missing → create with `createdAt` = now minus `ageDays` (data, 7-90) so real new groups stay above demo ones on the board.
   - Group fields: `name`, `slug`, `city`, `lookingFor` (≤ 60, `GROUP_LOOKING_FOR_MAX`), `bannerImage` `https://picsum.photos/seed/demo-<slug>/1200/675` (picsum is in `next.config` `remotePatterns`), `type: PUBLIC`, `isAcceptingMembers: true`, `description: null`, `tags` set to exactly the L2.
   - **Sections**: delete the group's sections and create order 0 (About) and order 1, both `PUBLIC`, `originalLang: 'lv'`, lv + en translations (Section 3).
   - **Memberships**: owner (OWNER) + 3-9 demo users (MEMBER). Delete memberships of demo users not in the data entry; upsert the listed ones; leave all other memberships.
   - **Events**: upsert by `(groupId, slug)`, slug = `slugify(lv title)`; set `startDate`/`endDate` from the run date (Section 4), `city` = event city or group city, `visibility: PUBLIC`, `joinMode: OPEN`, `creatorId` = owner, translations lv + en (upsert by `(eventId, lang)`). Demo events no longer in the data → delete. Attendance: upsert GOING for the listed demo users; delete demo users' attendance not listed; leave real users'.
   - **Announcements**: delete posts in the group authored by demo users, create the 2 data posts (`visibility: PUBLIC`, `title` + `content`, author = owner, `createdAt` = now minus `daysAgo`).
5. **Stale demo groups**: demo groups not in the data → delete (cascade).
6. **Coverage report**: list every `ACTIVE` L2 (live, including admin-made ones) with its demo group count; print those with 0 under "no demo group" (warning, exit 0). Print totals: users, groups, events, posts.

`--remove` (`npm run db:demo -- --remove`): delete all demo groups, then all demo users; leaves the 20 L2s (they may carry real groups by then). Prints counts.

No `revalidatePath`/`revalidateTag` is possible from the script: board caches catch up within their `revalidate` window (60-300 s, discovery.service.ts:63, :99). Say so in the final log line.

The script logs plain text, exits 1 on an exception, and always `$disconnect()`s.

## 2. Data files `prisma/demo-data/` (D1-1 types; content per session)

- `types.ts`: `DemoL2 { l1: string; slug: string; lv: string; en: string }`, `DemoUser { key; name; username; bio; cities }`, `DemoGroup` (fields below), `DemoEvent`, `DemoPost`, `Text = { lv: string; en: string }`.
- `taxonomy.ts`: the 20 L2s exactly as in the owner's plan (l1 / slug / lv), with en titles: Quiz nights, Gardening, Model building, Swimming, Basketball, Road trips, Kayaking, Science talks, Tabletop RPGs, Swing, Jam sessions, Sauna, Theatre, Ceramics, Cat lovers, Horse riding, Pilgrimages, Family outings, Debate clubs, Community gardens.
- `users.ts`: 15 users, key = username; email built by the script as `<username>@demo.ejam.invalid`; usernames prefixed `demo_` (unique column); fantasy Latvian names (e.g. "Zvaigžņu Mārīte", "Kapteinis Mencis"); bio lv one line starting "Iedomāts demo dalībnieks."; `avatarSeed` = username.
- `groups-<l1>.ts`: an array of `DemoGroup` per L1. `index.ts` concatenates them.

`DemoGroup`: `slug` (stable key, = `slugify(name)`), `l2`, `name`, `city`, `lookingFor`, `ageDays`, `owner` (user key), `members` (user keys), `tagline: Text`, `about: Text` (the rest of the About text, HTML paragraphs), `second: { title: Text; body: Text }`, `events: DemoEvent[]` (2-3), `posts: DemoPost[]` (2).
`DemoEvent`: `title: Text`, `description: Text`, `location`, `city?`, `isOnline?`, `inDays` (2-40), `hour` (Riga local), `hours` (duration, default 2), `going` (user keys).
`DemoPost`: `title`, `content` (lv only), `daysAgo`.

## 3. Content rules (all sessions)

Read `docs/handbook/voice.md` sections "Rules" and "Say, not" first.

- **Names**: whimsical Latvian fantasy / sci-fi, clearly not a real club, tied to the L2 ("Kaķu kosmosa programma" for cat-lovers, "Mēness laivotāju brālība" for kayaking). No real brands, people, venues' trademarks or political parties; religion and politics groups stay gentle and non-partisan (a "Lietus dievu svētceļnieki" walk, a "Robotu parlamenta debašu klubs").
- **About (section order 0)**, title from `DEFAULT_SECTION_TITLES.about` values ("Par mums" / "About us", check lib/constants), content HTML:
  1. `<p><strong>Iedomāta demo grupa.</strong> {tagline.lv}</p>` (en: `<strong>An imaginary demo group.</strong>`). This first paragraph becomes the card tagline, so the tagline sentence is the group's own one-line pitch (≤ 200 chars so the excerpt keeps it whole).
  2. `{about}`: 1-2 short paragraphs in the group's voice.
  3. `<p>Šī grupa ir izdomāta, lai parādītu, kā Ejam Kopā izskatās. Gribi īstu? <a href="/lv/create">Izveido līdzīgu grupu</a>.</p>` and the en twin with `/en/create`. One shared constant per language in `prisma/demo-data/types.ts` (or a `copy.ts`), not repeated per group. The builder confirms the `create` route path and that the section sanitiser keeps the link.
- **Second section (order 1)**: a practical or fun section ("Ko ņemt līdzi", "Mūsu tradīcijas", "Biežāk uzdotie jautājumi"), 2-4 sentences, lv + en.
- **lookingFor**: lv, ≤ 60 chars ("Kāds, kas prot stūrēt kanoe", "Vēl divi bundzinieki").
- **Events**: 2-3 per group, spread `inDays` over 2-40 so a monthly re-run always leaves upcoming ones; mix evenings and weekend days; at least one online event per ~8 groups; locations are generic places ("Kāda pagalma lapene, Āgenskalns", "Vērmanes dārza strūklaka") not real businesses; lv + en title and 1-3 sentence description.
- **Announcements**: 2 per group, lv, title ≤ 60 chars, 1-3 sentences, `daysAgo` 1-20.
- **Members**: 4-10 incl. owner, spread so every demo user is in 8-25 groups and owns 3-5.
- **Cities**: spread over all active cities; Riga about a third.
- Typography: Latvian quotes and diacritics correct; en is natural English, not word-for-word.

### Dates (D1-1)

`rigaDate(inDays, hour)`: the date `inDays` from today in Europe/Riga at `hour:00` Riga time, converted to UTC (compute the Riga offset with `Intl.DateTimeFormat('en', { timeZone: 'Europe/Riga', timeZoneName: 'shortOffset' })`); the container runs in UTC, so `setHours` (seed.ts:140) would be 2-3 h off. `endDate` = start + `hours`.

## 4. Command, image and workflow (D1-1)

- `package.json` scripts: `"db:demo": "tsx prisma/demo.ts"`.
- `Dockerfile` builder, next to the seed compile (line 22): `RUN npx tsc prisma/demo.ts --esModuleInterop --target ES2022 --module CommonJS`. It emits `prisma/demo.js` and `prisma/demo-data/*.js`, which the runner's `/app/prisma` copy carries. Locally the builder runs the same `tsc` line once to prove it compiles, then deletes the emitted `.js` (never commit them; add `prisma/demo.js` and `prisma/demo-data/*.js` to `.gitignore`).
- `.github/workflows/demo.yml`: `name: Demo content`, `on: workflow_dispatch` with input `mode` (choice `apply` | `remove`, default `apply`), job steps copied from `seed.yml` (checkout, SSH setup), then:
  ```sh
  c=$(docker ps --filter 'name=^ejam-kopa-app-' --format '{{.Names}}' | head -n1)
  test -n "$c" && docker exec "$c" node prisma/demo.js $ARGS
  ```
  inside the ssh command, `ARGS` = `--remove` when `mode == remove`. Any running colour works (same DB). The P1 container names are `ejam-kopa-app-<colour>-<n>` (docker-compose.server.yml:38-93); `seed.yml` (pre-P1 name) is deleted in D1-1.
- The workflow only works once an image with `demo.js` is live (after D1 is pushed and deployed).

## Acceptance

Local, on `npm run db:seed` data:
1. `npm run db:demo` runs clean; the coverage report shows 0 ACTIVE L2 without a demo group and ~55 groups, 15 users.
2. A second run prints the same totals; `SELECT count(*)` of groups, events, posts, memberships, sections are unchanged between runs; event `startDate`s move if the clock moved.
3. Seed groups untouched: their count and `updatedAt` are identical before and after both runs.
4. A real (seed) user joined to a demo group and marked GOING on a demo event keeps both after a re-run.
5. `npm run db:demo -- --remove` leaves exactly the seed rows plus the 20 L2s.
6. The Dockerfile `tsc` line compiles; `node prisma/demo.js` runs against the local DB.
7. Browser (D1-3, `npm run dev`): `/lv` board and two themes show demo cards with "Iedomāta demo grupa." taglines and banners; a demo group page in lv and en shows both sections, the create link works, events are upcoming, the latest announcement shows; 360 and 1280 px.
8. `npm run typecheck`, `npx eslint prisma/demo.ts prisma/demo-data`, `npm run i18n:check` pass. CI visual unchanged (no screen listed).

After push and deploy (owner or orchestrator): run the workflow with `apply`, check `/lv` on ejam.lumm.eu within 5 minutes.

## Risks

- **`seed.yml`** (pointed at the pre-P1 container, and would wipe every group on production) was deleted in D1-1 (Owner question 3).
- **Slug clash with a real group** in the same L1: skipped with a warning, the coverage report shows the gap; rename the demo entry.
- **Admin rejects or merges a demo L2**: Invariant 5 keeps the admin's choice; the group for it is skipped. A merge moves the demo group's tag like any group.
- **Real users join demo groups** and later see them vanish on `remove`: acceptable at prototype stage; the About text says it is imaginary.
- **Content volume** (~55 groups x lv + en) is most of the work: keep each `groups-<l1>.ts` to its session, write in one pass, don't re-read finished files.
- **Picsum** images are random per seed string and may show something odd; acceptable, same as seed.
