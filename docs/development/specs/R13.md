# R13 spec · Templates (palette + style)

Just-in-time spec for release R13 of the [build plan](../build-plan.md) (card "R13 · Templates"), written 20 Oct 2026 against `main` at `4b12d6b` (R1a–R11b live), Next.js 16, Tailwind v4, Prisma 6. Owner-approved; **built before R12**. Frozen once R13 is pushed.

**Problem.** Admin → Dizains presets (`THEME_PRESETS` in `lib/constants/theme.ts`, emitted by `lib/theme/css.ts`) change colours and fonts only. Shape is hardcoded in components (`rounded-full/xl/2xl`, `border border-border`, blurred `shadow-premium`), so every preset looks the same.

**Design.** A **template = palette + style**. A palette is today's preset (colours per mode + fonts). A **style** is a new, code-defined set of shape tokens: radius scale, line width, line colour (soft divider colour vs ink), card and control shadow (soft vs hard offset, no blur), press effect (translate on `:active`), heading weight. Two styles:

- **`calm` "Mierīgs"**: today's look, the default; **zero visual change** for the published site.
- **`bold` "Drosmīgs"**: neobrutalist (reference: neobrutalism.com/templates/neoflux): 2 px ink lines, hard offset shadows of about 4 px, small corners, flat strong colours, buttons that press down. Paired with a new yellow-led palette **`sun` "Saule"**.

**Rules touched (none owned; AR-69 stays R1b's):** [AR-69](../redesign.html#AR-69) Admin → Dizains (gains a fourth part, Stils), [AR-08](../redesign.html#AR-08) Shapes (stays the `calm` definition; `bold` is the owner-approved alternative), [AR-07](../redesign.html#AR-07) Fonts (Literata/Commissioner stay the default palette's fonts; Archivo Black is added as a pickable heading font). Rule text: `scripts/redesign/gen.mjs` 94, 95, 166. No drawing: R13 is built from the rules (AR-02) and this spec.

**Data:** one additive migration, `add_site_theme_style_key`.

**Size and split: L, two build sessions**, each reviewed and pushed on its own (both touch `messages/*.json` and the build plan, so R13-2 starts after R13-1 is pushed):

About 25 files, four commits. After R13-1, choosing Drosmīgs already restyles buttons, chips, tags, menus, pop-ups, dialogs, toasts and every `rounded-*` on the site.

## Invariants (must stay exactly as today; the reviewer checks each)

1. **Calm is today, pixel for pixel.** With `styleKey = calm` (every existing row after the migration) the computed `border-*`, `border-radius`, `box-shadow`, `translate` and heading `font-weight` of every swept element equal today's values (Acceptance A1 gives the method).
2. **Taxonomy Law / zero flicker.** All theme and style variables come from the server `<style id="site-theme">` in `app/layout.tsx`; no client code resolves a style, no `data-style` attribute toggled on the client, no class switch after hydration.
3. **Only code values reach the `<style>` block.** `styleKey` is validated against `THEME_STYLE_KEYS`; the CSS values come from `THEME_STYLES` in code; a stored key that no longer exists falls back to `calm` (as `toContext` does for colours today).
4. **Preview, then publish** stays the flow of AR-69: the style is part of the draft; the preview cookie (`THEME_PREVIEW_COOKIE`) shows it to the signed-in site admin only; publishing expires `THEME_CACHE_TAG`.
5. **Contrast floor** unchanged (`themeContrastIssues`, `CONTRAST_TOO_LOW` in `ThemeService`); the Saule palette passes it in both modes.
6. **Category colour never on site buttons** (AR-06); the ink line is the foreground colour, never a category tone.
7. **Dividers stay dividers.** One-sided rules (`border-t/b/l/r border-border`, `divide-border`) keep the palette's `--border`; only edges of surfaces and controls take the style's line.
8. **Avatars, dots, the switch knob, unread badges and the logo circles stay round** (`rounded-full`) in both styles.
9. **Motion respects `prefers-reduced-motion`** (the press keeps its position change, loses its transition).

## 0. Motivation and design alignment

- **Constants Law.** Styles are a static list: `THEME_STYLE_KEYS`, `THEME_STYLES` live in `lib/constants/theme.ts` next to `THEME_PRESETS`; Zod (`lib/validations/theme.ts`), the service, the CSS emitter and the editor import from there.
- **Service Law.** `ThemeService` reads and writes `styleKey`; `ThemeContext` carries it. No Prisma outside the service.
- **Taxonomy Law.** Style tokens are CSS variables emitted with the colours by `themeCss()` on the server. Tailwind utilities already read `var(--radius-*)` and `var(--shadow-*)` at use time, so overriding the variables in `html:root` restyles every existing `rounded-*` and shadow without touching components.
- **Reuse before creating.** Tokens first, sweep second: the `@theme` tokens do most of the work; the sweep only adds three utilities (`line`, `frame`, `press`) and one radius (`rounded-pill`) where a hardcoded class cannot follow a token.
- **Handbook.** Design.md's Foundations gain a "Templates" paragraph; `calm` keeps every existing Shape, Depth and Type statement true.

| Token (CSS var) | `calm` | `bold` |

| `--line-width` | 1px | 2px |
| `--line-color` | `var(--border)` | `var(--ink)` |
| `--frame-width` (edge on things that have none today) | 0px | 2px |
| `--ink` | `var(--foreground)` | light: `var(--foreground)`; dark: `color-mix(in srgb, var(--foreground) 85%, var(--background))` |
| `--shadow-card` | `none` | `4px 4px 0 0 var(--ink)` |
| `--shadow-control` (new) | `none` | `3px 3px 0 0 var(--ink)` |

| `--shadow-dialog` | not emitted | `6px 6px 0 0 var(--ink)` |

| `--shadow-room` (space a clipping parent leaves for the shadow) | 0px | 5px |
| `--heading-weight` | 600 | 700 (a single-weight heading font wins, 3.3) |

## 4. CSS tokens and utilities (R13-1 commit 2)

### 4.1 `lib/theme/css.ts`

- New `themeStyleVars(style: ThemeStyleTokens, headingFont: ThemeFontId): Vars` builds the table in 3.1. `themeCss(def)` spreads it into the `html:root` block; the dark `--ink` (bold only) goes into the `html.dark:root` block.
- `themeSampleVars(...)` gains a `styleKey` argument and sets the style vars **and** `--ink`, `--line-color`, `--shadow-card`, `--shadow-control`, `--shadow-premium`, `--shadow-dialog` again on the sample element. Reason: a custom property holding `var(--foreground)` is resolved where it is declared (the root), so the sample's own foreground would not reach the root-resolved ink otherwise (the same reason the `--color-*` tokens are set again there today). For `calm` the sample sets the calm values explicitly (`--radius-*` to Tailwind's defaults, shadows to the globals values), so a calm card inside the editor is not bold while a bold draft is previewed site-wide.

### 4.2 `app/globals.css`

- `:root`: add the calm values of `--line-width`, `--line-color`, `--frame-width`, `--ink`, `--shadow-control`, `--press-shift`, `--shadow-room`, `--heading-weight` (the no-theme fallback, like the colours).
- `@theme`: state the radius scale explicitly at today's values (`--radius-md: 0.375rem` … `--radius-3xl: 1.5rem`, check them against `node_modules/tailwindcss/theme.css` before writing) plus `--radius-pill: 9999px`; add `--shadow-control: var(--shadow-control)` next to the other shadows (the unlayered `:root` value wins, as for `--shadow-card` today).
- New utilities (Tailwind v4 `@utility`):
  - `line`: `border-style: solid; border-width: var(--line-width); border-color: var(--line-color);` — replaces `border border-border` on **edges** (calm: identical to today).
  - `frame`: same with `--frame-width` — for surfaces and filled controls that have no edge today (calm: 0 px, no change).
  - `press`: `transition: translate 120ms ease-out;` and `&:active:not(:disabled) { translate: var(--press-shift) var(--press-shift); --tw-shadow: 0 0 #0000; }`; inside `@media (prefers-reduced-motion: reduce)` no transition. Uses the `translate` property, so it never fights `soft-press` (`scale`). Clearing `--tw-shadow` drops only the shadow and keeps rings (focus, `ring-inset`).
  - `shadow-room`: `padding-inline-end: var(--shadow-room); padding-block-end: var(--shadow-room);` for scrollers and `overflow-hidden` parents that would clip a hard shadow (calm: 0).
- Base `h1–h4`: `font-weight: var(--heading-weight); font-synthesis-weight: none;` and the same `font-synthesis-weight: none` on `.font-heading` (Archivo Black has one weight; `font-semibold` on a title must not fake-bolden it).

## 7. The sweep outside `components/ui/` (R13-2)

Counts at `4b12d6b` (`grep -rEo`): `border-border` 251 in 130 files, `rounded-full` 209 in 129, `rounded-2xl` 82 in 69, `rounded-[…]` 11, `shadow-premium` 22 in 19, `active:scale` 11 in 10. Radii and shadows already follow tokens after R13-1; the sweep only handles what cannot:

1. **Edges.** `border border-border` (both words, four-sided) on an element that is a surface or control (has `bg-surface*`, `bg-background`, `rounded-*`, or is an `input`/`select`/`textarea`) → `line`. One-sided and `divide-*` stay (invariant 7). `border-2 border-border` → `line` too (bold already 2 px; calm keeps 1 px only if today is 1 px: leave `border-2` cases as they are and list them in the commit message).
2. **Cards.** Card surfaces (`bg-surface` + `rounded-2xl|3xl`, 56 files) get `shadow-card`; group cards (`components/discovery/…GroupCard*`, `CreateCard`) also `line` (they are the bordered card of the handbook). Panels and sections inside a page frame get `frame`. Divided rows (phone group row, event rows) stay flat (handbook Shape).
3. **Pills.** `rounded-full` on a control or tag (filter buttons, `DayStrip`, `QuickChoices`, `DateChoices`, `AlsoMatchesLine`, `CategoryDrawer` chips, `L1Picker`, `TagResults`, `MobileNav`, `UserMenu`/`LanguageMenu` triggers, `SaveRow`, `SectionFormFooter`, auth forms) → `rounded-pill`; avatars and dots stay.
4. **Clipping.** Horizontal scrollers (day strip, chip rows, card rails) and `overflow-hidden` parents of a `shadow-card`/`shadow-control` child get `shadow-room`.
5. **Arbitrary radii** (`rounded-[1.5rem]`, `rounded-[2rem]`, …) → tokens with calm-equal values (`rounded-3xl` = 24 px; 2 rem → `rounded-4xl`, add `--radius-4xl` to `@theme` if absent, bold 12 px).
6. **Inline press** (`active:scale-*` on custom buttons) stays; filled custom buttons that look like `Button` switch to `buttonClass()` where that is a one-line change, else get `frame shadow-control press`.

Commits by area so each is reviewable: (5) discovery, shell, panels, search; (6) groups, events, me, messages, notifications, forms; (7) admin, auth, translate, feedback, handbook demos. A mechanical `sed` per pattern is fine, followed by reading the diff of every file (the classes must stay sorted the way the file had them; no other change).

## 12. Risks

- **Calm drift** from the sweep (a `line` where the element had `border-2`, a radius token 2 px off). A1 catches it; run it per commit, not at the end.
- **Root-resolved variables** in the sample: if `themeSampleVars` misses one of the vars in 4.1, the sample shows the root's ink or shadow. The reviewer previews bold site-wide and then picks calm in the editor: the sample must be calm.
- **Stale cache** after the deploy: contexts cached by the old code lack `styleKey`; the `?? calm` fallback in `themeCss` covers it (invariant 3).
- **Hard shadows clipped** by `overflow-hidden` and scrollers; `shadow-room` is the fix, the 360 px check finds them.
- **Ring vs shadow**: Tailwind v4 composes ring and shadow in one `box-shadow`; `press` clears only `--tw-shadow`. Don't write a raw `box-shadow` in any utility.
- **Dark-mode ink** may feel loud at 2 px; the 85 % mix is the default (owner question 3).
- **Archivo Black as a body font** is legal in Fonti but poor; the sample makes that visible, no validation rule.

## 13. Out of scope

- Per-group styles (styles are site-wide; groups keep their category accent only), more than two styles, an editor for individual style values, style-specific icons or illustrations, category tones per style, changes to the logo's shape.

## 14. Owner questions (the builder uses the default unless the owner objects)

1. **Template coupling.** **Default: a preset carries its style** (Saule → Drosmīgs, the others → Mierīgs), and the Stils part can change it afterwards, so any palette can be paired with any style.
2. **Logo font.** The logo uses `font-heading`, so with Saule it is set in Archivo Black. **Default: the logo follows the template's heading font** (AR-03's "Literata" is the default palette's heading font), circles and colour unchanged.
3. **Lines in dark mode (Drosmīgs).** **Default: ink = the foreground mixed 85 % with the background** (light lines and shadows on the dark page, slightly softened); the alternative is full-strength foreground.
