## 0. Motivation and design alignment

- **What is wrong today.** Two forms carry their own copy of three small pieces: `LangSwitch` (an LV | EN segmented switch with a dot per language, sr text "teksta vēl nav"), `OriginalLangControl` (a second 11 px LV | EN switch, "Oriģinālvaloda", locked when empty) and `UntranslatedNotice` ("Vēl nav iztulkots … Sākt ar latvisko tekstu", ICU `select` on lv/other only). The event form wraps them in `EventLangBar`; `SectionEditForm` places them itself and hides them for a new section. Two switches side by side read as one puzzle (notes cmv9b0tth, cmv9bemab), the original language looks unselected (cmv9az6sn), nothing says a second version can be added (cmv9b1v6h), and every piece hard-codes two languages.
- **One piece.** `components/ui/LanguageEditor.tsx` replaces all four. One language on screen at a time, named in one control ("Valoda: Latviešu ▾"); the original is always one of them and says so; adding a version is a visible button. It owns no text: every draft stays in the form's own state (react-hook-form for events and the group wizard, `sections` state for sections), so switching language never loses text (cmv9b0tth).
- **Service Law.** No Prisma outside services. The group wizard's per-language "Par mums" goes through `GroupService.createGroup` (section 6.3); the editable texts keep coming from `EventService.toEditableTexts` and `toEditableSection`, made language-generic (section 5).
- **Context Law.** Nothing new is prop-drilled; the editor takes only the language state and callbacks of the form that holds it.
- **Defensive Coding.** The editor is `disabled` while its form saves (`isPending`); the validation stays in the shared Zod schemas (`lib/validations/event.ts`, `section.ts`, `group.ts`), now built over `TEXT_LANGS` instead of `{ lv, en }` literals.
- **Action Consistency.** No new action. `createGroup` keeps `ActionResponse<T>`; its validation uses the new `groupCreateSchema`; codes stay registry codes (`TITLE_TOO_SHORT`, `TITLE_REQUIRED`, `ORIGINAL_LANG_EMPTY`, `DESCRIPTION_TOO_LONG`).
- **Zero-Any, Constants.** Typed `Record<TextLang, T>` everywhere; languages from `LOCALES` (which also feeds `i18n/routing.ts`), names from `LOCALE_NAMES`; new `UI` names `languageEditor`, `languageEditorMenu`.

## 2. The component

### 2.1 What it looks like (one default each)

One bar above the language-dependent fields, then the fields, then (only when it applies) one hint line.

```
Valoda  [ Latviešu  (Oriģināls)  ▾ ]   Citas valodas: English      + Pievienot tulkojumu
──────────────────────────────────────────────────────────────────────────────────────
<the form's fields for the language on screen>
```

- **Label and trigger.** A visible quiet label "Valoda" (13 px, `text-foreground-muted`) and the trigger button: the language's own name (`LOCALE_NAMES`, with `lang={code}`), then `Badge tone="muted"` "Oriģināls" when it is the original, then `ChevronDown` 16 px. Pill, `border border-border bg-surface`, 14 px / 500, `h-11 md:h-9`, hover `bg-tint`, open `bg-tint`, focus ring `outline-primary` (as `LanguageMenu`). The trigger's name is `aria-labelledby="{labelId} {triggerId}"` → "Valoda Latviešu Oriģināls".
- **The original is always set and always named** (cmv9az6sn). A new text starts with the UI locale as original (`toTextLang(useLocale())`, as today), so the first language on screen carries "Oriģināls" from the first paint. There is no separate original-language switch any more.
- **"Citas valodas:"** (quiet 13 px) lists the other versions the text has (section 2.4), each name a small text button in the site colour that switches to it; up to 3 names, then "+N" which opens the menu. Hidden when there is only one version. This is the always-visible sign that another version exists (cmv9b1v6h).
- **"+ Pievienot tulkojumu"**: `Button variant="quiet" size="sm"` with `Plus` 16 px, shown while a language without a version remains. With one language left (today: always) a click adds it at once; its accessible name says which ("Pievienot tulkojumu: English"). With more left it opens a second small menu (same `useMenu`/`MenuPanel`) listing them.
- **Fluid.** One flex row with `flex-wrap gap-x-3 gap-y-2`; at 360 px the label + trigger take line one, "Citas valodas" and the add button wrap under it; no fixed widths except the menu (240 px, `max-w-[calc(100vw-24px)]`). From 768 px it is one line inside every current form width. A thin `border-b border-border pb-3 mb-4` separates it from the fields.

### 2.2 The menu (opened by the trigger)

`useMenu()` + `MenuPanel placement="anchor" align="start"`, label "Teksta valodas" (`dataUi={UI.languageEditorMenu}`):

1. A quiet first line (not a row, `describedBy`, like the "…" menu's role line): "Oriģināls ir valoda, kurā raksti. Apmeklētāji, kuriem nav savas valodas, redz to."
2. One `menuitemradio` row per version, original first, then in `LOCALES` order: `Check` on the one on screen (empty 17 px slot otherwise), the name (`lang={code}`), trailing (`MENU_TRAILING_CLASS`): "Oriģināls" for the original, else its state: "ir teksts" / "tukšs"; a language with a validation problem shows "jālabo" in `text-danger` instead (wins over the others).
3. `MenuSeparator`, then rows about the language on screen, **hidden, never greyed** (design.md, the "…" menu rule):
   - "Padarīt par oriģinālu": the language on screen is not the original and is filled.
   - "Noņemt tulkojumu": the language on screen is not the original. If it has text, it asks first in a `ConfirmPopover` anchored to the trigger (`anchorRef`): "Noņemt English tulkojumu? Tā teksts pazudīs, kad saglabāsi." · "Noņemt" (destructive). If it is empty, it goes at once.
   - "Pievienot tulkojumu" (the same as the button; kept in the menu for keyboard users already in it), while a language remains.

Keys, focus and closing are `useMenu`'s (Enter, Space, arrows, Home/End, Esc returns focus to the trigger, click outside, Tab). **Default (spec): a dropdown menu, not a `<select>`**: rows carry state words and actions, which a native select cannot; and it matches the header's `LanguageMenu`.

### 2.3 Behaviour (one default each)

| Action | Result |
|---|---|
| Choose a language (menu row or "Citas valodas" name) | `onLangChange(code)`; the fields show that language's draft; nothing is copied, cleared or saved; focus back on the trigger (menu) or stays on the name button |
| Add a translation | the language joins the versions, `onLangChange(code)`; its fields are empty; focus moves to the first field inside the editor's children (`input, textarea, [contenteditable="true"]`); the translation hint shows (below) |
| Make the original | `onOriginalLangChange(code)`; no text moves (the server rule: it only decides which row visitors fall back to); the old original stays as a translation; the form re-validates every language; a polite live region says "English tagad ir oriģināls" |
| Remove a translation | `onClear(code)` (the form sets that language's fields to empty), it leaves the versions, the original comes on screen; live region "Tulkojums noņemts". Saving then drops its row (events: `textRows`; sections: the empty non-original row is deleted by `upsertSection`) |
| Copy from the original | the hint's button "Sākt ar oriģināla tekstu" calls `onCopyFromOriginal(code)` (the form copies the original's fields into that language; sections map a built-in title "Par mums" → "About us" as today); the rich-text editors reload (the forms' existing `rev` key) |

**Hint line (one at a time, under the fields' top, `text-sm text-foreground-muted`, a tinted 12 px box like today's notice):**
- On a translation that is empty: "Kamēr tulkojums ir tukšs, apmeklētāji redz oriģinālu (Latviešu)." + `Button variant="secondary" size="sm"` "Sākt ar oriģināla tekstu".
- On the original when it is empty but another version has text (the original's text was removed): "Oriģinālvalodā (Latviešu) vēl nav teksta. Uzraksti to vai padari citu valodu par oriģinālu." No automatic switch of the original: the author decides (menu → "Padarīt par oriģinālu" on the other language).
- A problem in a language not on screen: `role="alert"` "English versijā kaut kas jālabo." + text button "Atvērt" (switches to it). This replaces `eventWizard.originalLangTitleError` / `otherLangTitleError`.

**On submit** (event "Tālāk"/"Saglabāt", section "Saglabāt sadaļu", wizard "Tālāk"): when validation fails only in languages not on screen, the form switches to the original if it has a problem, else to the first language (in `LOCALES` order) that has one, and focuses its first invalid field. The forms do this through `firstLangWithError(errorLangs, original)` from `lib/translations.ts`.

### 2.4 Which languages are "filled" and which are "versions"

- **Filled** = the language holds text a person would read in any of the form's language fields: plain fields by `trim() !== ''`, rich fields by `hasText()`. Per form, one predicate next to its schema:
  - `isEventTextFilled(t)` in `lib/validations/event.ts` (moved from `EventLangBar.isEventLangFilled`): title, description or instructions.
  - `isSectionTextFilled(t)` in `lib/validations/section.ts` (moved from `SectionEditForm.isLangFilled`): content, or a title that is not an untouched built-in title (`isDefaultSectionTitle`), so the seeded "About us" row does not count as an English version.
  - group wizard: `hasText(about[lang])`.
  Each form passes `filled = langRecord((l) => isXFilled(texts[l]))`.
- **Versions** (the languages listed in the menu and in "Citas valodas") = the original ∪ every filled language ∪ the languages added in this editing session and not removed. The editor keeps the "added" set itself (`useState`, seeded at mount from original ∪ filled), because an added-but-still-empty translation exists only on screen; it is never sent anywhere (an empty language saves as no row). Making another language the original adds the old original to the set, so it does not vanish while empty.
- **It shows** as the trailing state word in the menu, the "Oriģināls" badge, and the presence in "Citas valodas". No dots (the old dot was the "weird" part).

### 2.5 API

```ts
// components/ui/LanguageEditor.tsx ('use client', ≤ 150 lines; the add menu and the remove pop-over may live in
// components/ui/language-editor/{LanguageMenuRows,AddTranslationButton}.tsx, ≤ 90 lines each)
import type { ReactNode } from 'react';
import type { TextLang } from '@/lib/translations';

export interface LanguageEditorProps {
    /** The language on screen; the form owns it (its field names depend on it). */
    lang: TextLang;
    onLangChange: (lang: TextLang) => void;
    originalLang: TextLang;
    onOriginalLangChange: (lang: TextLang) => void;
    /** Which languages hold readable text (section 2.4). */
    filled: Record<TextLang, boolean>;
    /** Languages with a validation problem (errors or over a counter's limit). */
    errorLangs?: readonly TextLang[];
    /** Copies the original's fields into `lang` (nothing is saved). */
    onCopyFromOriginal: (lang: TextLang) => void;
    /** Empties every field of `lang` (removing a translation). */
    onClear: (lang: TextLang) => void;
    /** While the form saves. */
    disabled?: boolean;
    /** UI elements specimen only. */
    initialMenuOpen?: boolean;
    /** The fields for `lang`. They set their own `lang` attribute; the wrapper does not (its labels are UI text). */
    children: ReactNode;
}
export default function LanguageEditor(props: LanguageEditorProps): JSX.Element;
```

Root `<div data-ui={UI.languageEditor}>`: the bar, the hint line, a hidden `aria-live="polite"` span, then `children` in a `div` used only to find the first field after "add".

**Helpers in `lib/translations.ts`** (all languages from `TEXT_LANGS`, no `lv`/`en` literals):
- `langRecord<T>(make: (lang: TextLang) => T): Record<TextLang, T>`: the one typed builder (one `Object.fromEntries` with a cast inside, commented), used for defaults, `filled` and the services' editable texts.
- `toTextLang(value)`: `TEXT_LANGS.includes(value)` → value, else `DEFAULT_LOCALE` (today it maps anything not `en` to `lv`).
- `firstLangWithError(errorLangs, original): TextLang | null`.

**`components/ui/Menu.tsx` (small edits, stays < 110 lines):** `MenuPanel` gets `align?: 'start' | 'end'` (default `'end'` = today's `right-0`; `'start'` = `left-0`) for `placement="anchor"`; `MenuItemButton` gets `current?: boolean` → `role="menuitemradio"` + `aria-checked`, as `MenuItemLink` already does.

## 3. Keyboard and screen reader

- Tab order: trigger → "Citas valodas" names → "+ Pievienot tulkojumu" → the fields. The trigger is a WAI-ARIA menu button (`useMenu`'s `triggerProps`: `aria-haspopup="menu"`, `aria-expanded`, `aria-controls`).
- Rows are `menuitemradio` with `aria-checked`; the state word is part of the row's text, so it is read ("English, tukšs").
- The remove pop-over traps focus and returns it to the trigger (`ConfirmPopover`).
- Live region (polite) for "tagad ir oriģināls" and "Tulkojums noņemts"; the cross-language problem line is `role="alert"`.
- Every field already sets `lang={lang}` (title inputs; the rich-text wrapper `div lang={lang}` in sections; the event form's editors get the same wrapper: a 1-line fix).
- Touch targets: trigger, add button and name buttons ≥ 44 px tall below 768 px (`h-11`, name buttons `min-h-11 md:min-h-0` with padding).

## 4. Validation and counters

- **Required in the original language only.**
  - Event: title ≥ 3 in the original; a title started in another language must also be ≥ 3 (unchanged `superRefine`); description and instructions optional everywhere.
  - Section: title required in the original (server `TITLE_REQUIRED` / `ORIGINAL_LANG_EMPTY`, unchanged). New on the client: "Saglabāt sadaļu" with an empty original title shows `errors.TITLE_REQUIRED` under the title (in the original language) instead of a server round trip.
  - Group wizard: "Par mums" optional in every language (as today); `DESCRIPTION_TOO_LONG` per language.
- **Schemas built over the locales** (scales to a third language with no form change):
  - `event.ts`: `texts: z.record(z.enum(TEXT_LANGS), eventTextSchema)` (Zod 4: an enum-keyed record requires every key, so the type stays `Record<TextLang, EventText>`); the `superRefine` loop already iterates `TEXT_LANGS`.
  - `group.ts`: new `groupCreateSchema = groupFormSchema.extend({ originalLang: z.enum(TEXT_LANGS), about: z.record(z.enum(TEXT_LANGS), z.string().max(GROUP_ABOUT_MAX, 'DESCRIPTION_TOO_LONG')) })` with `GROUP_ABOUT_MAX = 10000` (the existing limit, now a constant next to the schema) and `type GroupCreateValues`. `groupFormSchema` (settings, admin categorization, `updateGroup`) is unchanged.
  - `section.ts`: unchanged (one language per save).
- **Counters (R2b, AR-71).** Plain fields keep their `TextCounter` for the language on screen (title 120). A language over a limit counts as a problem: it is in `errorLangs` ("jālabo" in the menu) and holds the save back whichever language is showing: `TEXT_LANGS.some((l) => isOverLimit(texts[l].title, MAX))` replaces the `lv`/`en` pair in the event form and the current-language-only check in `SectionEditForm`. **Rich-text counters stay out** (R2b section 6.3: `RichTextEditor` stores HTML, needs a character-count extension; R9a/R9b).

## 11. Risks

- **Saving several languages of a new section in a row** (6.2): a failure after the first save leaves the section created with only some languages. The existing loop already handles it (stops, shows the error, keeps what was saved, the rest stays in the drafts as unsaved changes); the reviewer forces a failure once (e.g. a 121-char title in the second language is blocked on the client, so use the devtools offline toggle after the first request).
- **`z.record` with an enum key** must stay exhaustive in Zod 4 (it is: `z.partialRecord` is the optional variant). If `EventFormData` and the inferred type drift, typecheck shows it.
- **react-hook-form and per-language field names**: inputs are keyed by `lang` (`key={\`title-${lang}\`}`), as today, so `register` re-binds; the drafts live in the form values, not in the inputs. The rich-text editors remount from the form value (they emit on every update, no debounce), so nothing is lost on a switch (L4 proves it).
- **Changing the original while the old original is empty**: allowed (that is how an author recovers when the original's text was removed); the server accepts it because the new original has a title.
- **The group wizard's type change** touches the shared step components through `useFormContext<GroupFormValues>`; the extended type is a superset, so they keep compiling. `updateGroup` and the admin categorization form keep `groupFormSchema`.
