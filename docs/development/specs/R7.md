## Owner decisions (each with the default the build applies)

What the rules and drawings leave open. The builder applies the default; the owner confirms or changes it after seeing the build.

1. **Themes appear once letters are typed** (owner, 15 Oct, note cmv987j9t). With an empty field the search shows Kur and your recent searches, no theme chips; the only exception is a theme already chosen (for example the page's own category, which the search starts with), shown tinted with × so it can be cleared. The drawer and the Tēma button list all themes. A typed word (2+ letters) shows the themes whose name or Veidi match it (all of them, busiest first; themes with nothing in the place are left out).
2. **Events of private groups** are out of search and discovery too (a private group's event list would show the group): `eventWhere` adds the group's `type: 'PUBLIC'`, so Pasākumi, its counts and the day strip drop them as well. A member still sees them on the group's own Pasākumi. (Today they appear on discovery's Pasākumi: a leak against OD-07 found while writing this spec.)
3. **How many results.** Up to 5 groups and up to 5 upcoming events, each kind under its heading; "Rādīt visus rezultātus (N)" always carries the count (N = groups + upcoming events in the place, word and theme applied); no count when the word is under 2 letters and no theme is chosen.
4. **Members-only events are not in search**, also for members (the search shows only what anyone may see; discovery's Pasākumi still shows them to members after "Rādīt visus rezultātus").
5. **Recent searches.** The last 5 words, newest first, saved on this device only (never sent anywhere): when you press Enter, open a result or "Rādīt visus rezultātus" with a word of 2+ letters. Each has a × to remove it; no "clear all". The privacy page gains one sentence (section 8).
6. **The search's place.** It starts with the page's place on discovery (its `city`), else "Visur". Changing it in the search changes only the search; the page's filter changes when you press "Rādīt visus rezultātus".
7. **Where "Rādīt visus rezultātus" lands.** Grupas, unless the search found only events (then Pasākumi), or you opened the search on discovery's Pasākumi and it found events there (then Pasākumi). The word, the place and the chosen theme (as Tēma) go along.
8. **After a result.** The result opens its panel (R6) over the page you were on and the search closes; Back closes the panel and returns to that page (not to the search). Reopening the search starts with an empty field and the recent searches.
9. **Opening.** The desktop field opens the search on a click, a tap, on keyboard focus and on the first letter typed; Enter in the field is "Rādīt visus rezultātus" (as today's form). Esc closes the panel and keeps the word in the field; the field's × clears the word (never the place or the theme).
10. **Letters with marks.** Theme chips ignore marks ("speles" finds "Spēles"), but the database text search does not ("speles" does not find the group "Spēļu klubs"): Postgres needs the `unaccent` extension and a migration for that. Default: accepted for R7; a later item `add_unaccent_extension` is listed in section 15.
11. **Reads go through a route handler** (`GET /api/search`), not a Server Action: Next queues Server Actions one at a time and calls them mutations (`node_modules/next/dist/docs/01-app/02-guides/backend-for-frontend.md`, "Server Actions are queued"), which would make search-as-you-type wait behind each request and leave no way to cancel one. The handler answers `ActionResponse<T>` JSON so the client maps errors the same way. The unused `actions/discovery-actions.ts` goes.

## 0. Motivation and design alignment

- **Service Law.** One service call returns the whole search: `DiscoveryService.search(input, locale, viewerId)` composes the existing pieces (`groupWhere`, `eventWhere`, `getCounts`, `toGroupCard`, `toEventRow`, the cached taxonomy and categories) in a new helper file `lib/services/discovery-search.ts` (like `discovery-query.ts`). The route handler only validates, reads the session and calls the service. No Prisma outside services. The old `searchContextual` (categories as results, no place, past events, a `'sigulda'` fallback) and its unused action are deleted.
- **Privacy in the service, not the UI (OD-07).** Groups through `groupWhere` (PUBLIC, not hidden, ACTIVE non-wildcard category, public section text only); events through `eventWhere` (not hidden, now PUBLIC groups only) plus `visibility: 'PUBLIC'`; instructions are never searched or returned. The response carries no user data except the viewer's own "Eju"/"Gaida" tag on an event row, so it is `Cache-Control: private, no-store`.
- **Context Law.** The search sits in the header (outside any page), so it takes its data from its own fetch, never from `DiscoveryProvider`. Shared lists stop reading context they cannot have there: `PlaceList` takes `cities` and `counts` as props (discovery's `PlaceButton` passes them from its providers). The discovery page puts the "Atbilst arī:" matches into `DiscoveryState`; `AlsoMatchesLine` reads them with `useDiscovery()`.
- **Taxonomy Law / AR-06.** Theme chips carry their tone as `--c` from the service's category colour (dot and tint only); the highlight, links and "Rādīt visus rezultātus" are site colour. No `--accent`.
- **Defensive Coding.** The search request is debounced (200 ms), cancelled when a newer one starts (`AbortController`) and ignored if it is not the latest (sequence number): the latest query wins. The field's word is capped at 100 characters (the same cap as `parseDiscoveryParams`); the route validates with a shared Zod schema in `lib/validations/search.ts`. `localStorage` is read and written only inside try/catch; the search works without it.
- **Action Consistency.** No new Server Action; the route handler answers `{ success: true, data }` or `{ success: false, error: 'VALIDATION_FAILED' | 'ACTION_FAILED' }` (existing codes).
- **Zero-Any / Constants.** Typed result shapes (`SearchResults` in `lib/types/search.ts`); new constants `SEARCH_MIN_CHARS = 2`, `SEARCH_DEBOUNCE_MS = 200`, `SEARCH_ROWS_MAX = 5`, `SEARCH_IDLE_THEMES = 8`, `SEARCH_RECENT_MAX = 5`, `SEARCH_RECENT_KEY = 'ek:recent-searches'`, `SEARCH_WORD_MAX = 100` in `lib/constants`; UI names added to `UI`.

## 2. Shared pure helpers

### 2.1 `lib/search-topics.ts` (new, pure, ≤ 70 lines; server and client)

```ts
export interface TopicSource { slug: string; title: string; color: string; subs: Array<{ slug: string; title: string; deeper: string[] }> }
export interface TopicMatch { kind: 'theme' | 'veids'; slug: string; l1Slug: string; title: string; color: string }
/** Themes whose title or any Veids/level-3 title contains the word, then Veidi whose title or level-3 title contains it. Marks ignored (foldText), 2+ letters, else []. */
export function matchTopics(word: string, topics: TopicSource[]): TopicMatch[]
```

Built from `TaxonomyService.getTaxonomy(locale)` (cached; ACTIVE only; `subs` from `subcategories` with `status === 'ACTIVE'`, `deeper` from their ACTIVE `tags` titles) filtered to the themes `DiscoveryService.getDiscoveryCategories(locale)` lists (non-wildcard; its `color`). A helper `toTopicSources(tree, categories)` in the same file does that join. Order inside the result is left to the caller (both callers sort by count).

### 2.2 `lib/recent-searches.ts` (new, client-only functions, ≤ 45 lines)

`readRecent(): string[]`, `saveRecent(word: string): void`, `removeRecent(word: string): void`. Key `SEARCH_RECENT_KEY`; value a JSON array of strings; newest first; duplicates removed case-insensitively (`foldText`); at most `SEARCH_RECENT_MAX`; words shorter than `SEARCH_MIN_CHARS` are not saved; anything that is not an array of strings reads as `[]`. **Every** `localStorage` access inside try/catch (private windows and blocked storage throw); a failure is silent. Nothing here is ever sent to the server.

### 2.3 `components/ui/Highlight.tsx` (new, server-safe, ≤ 35 lines)

`<Highlight text={name} word={q} />`: the first place where the word occurs, compared character by character after `foldText` on each character (so "spe" marks "Spē"; Latvian letters fold to one character each, so indices stay aligned), wrapped in `<mark className="bg-transparent font-semibold text-primary">`. A word under `SEARCH_MIN_CHARS` or no match → the plain text. No `dangerouslySetInnerHTML`.

### 2.5 `lib/types/search.ts` (new, ≤ 40 lines)

```ts
export interface SearchTheme { slug: string; title: string; color: string; count: number }
export interface SearchResults {
  word: string; theme: string | null; cities: string[];
```

## 3. Services

### 3.1 `lib/services/discovery-search.ts` (new, ≤ 140 lines) and `DiscoveryService.search`

`DiscoveryService.search({ word, cities, theme }, locale, viewerId?)` returns `SearchResults`. `discovery.service.ts` keeps a 3-line method that delegates; `searchContextual` and the `ScopedResult` type are deleted (the file shrinks by ~190 lines).

1. `const short = word.length < SEARCH_MIN_CHARS`. `query = short ? undefined : word`.
2. Topics: `toTopicSources(await TaxonomyService.getTaxonomy(locale), await DiscoveryService.getDiscoveryCategories(locale))`; an unknown `theme` is dropped (`theme = null`). The theme's L1 id comes from the categories list (for `groupWhere`'s `categoryId`).
3. Counts, in parallel: `getCounts({ kind: 'groups', cities, l1Slug: theme, query }, locale)` and `getCounts({ kind: 'events', cities, l1Slug: theme, query }, locale)` (no dates: upcoming; uncached with a word, cached without, as today). From them: `total.groups = g.total`, `total.events = e.total`; `elsewhere = cities.length ? (g.anyPlace - g.total) + (e.anyPlace - e.total) : 0`; `places = { cities: await CityService.listActive(locale), byCity: g.byCity, anyPlace: g.anyPlace }` (the Kur list counts groups, as discovery's Grupas does); a theme's count `= g.byCategory[slug] + e.byCategory[slug]`.
4. Themes: short word → the categories with count > 0, busiest first, first `SEARCH_IDLE_THEMES`; else `matchTopics(word, topics).filter(kind === 'theme')` with count > 0, busiest first. When a theme is chosen the list still comes back (the client hides the others, AP-06).
5. Rows, in parallel, **uncached** (search-as-you-type would fill the cache with one entry per typed word): `prisma.group.findMany({ where: groupWhere({ query, cities, categoryId }, lang), select: { …the card select of getGroups }, orderBy: { createdAt: 'desc' }, take: SEARCH_ROWS_MAX })` → `toGroupCard`; `prisma.event.findMany({ where: { AND: [eventWhere({ search: query, cities, category: theme ?? undefined, status: 'upcoming' }), { visibility: 'PUBLIC' }] }, include: EVENT_ROW_INCLUDE(lang), orderBy: { startDate: 'asc' }, take: SEARCH_ROWS_MAX })` → `toEventRow(e, lang, status)` where `status` comes from one `attendance.findMany({ where: { userId: viewerId, eventId: { in: ids } } })` when signed in, else null. Share the group card `select` with `getGroups` by moving it to a `GROUP_CARD_SELECT(lang)` constant in `group-card.ts` (both use it).
6. Short word and no theme → `groups: []`, `events: []`, `total` zeros (the client shows the recent searches instead); short word with a theme → the theme's rows (the busiest groups first is not needed: newest first, as discovery).
7. Never log the word (no `console.log`); errors are thrown to the route handler.

## 5. The search

### 5.1 `hooks/useSearch.ts` (new, client, ≤ 110 lines)

State: `word`, `theme: string | null`, `cities: string[]`, `results: SearchResults | null`, `loading: boolean`, `error: boolean`. `useSearch({ initialWord, initialCities, kind })`.
- Every change of word, theme or cities schedules a fetch after `SEARCH_DEBOUNCE_MS` (a theme or place change: at once). The fetch is `fetch('/api/search?' + params, { signal })` with `q`, `city` (comma list), `theme`, `kind`, `locale` (`useLocale()`). Before each fetch the previous one is aborted; a response whose sequence number is not the latest is dropped. **The latest query wins.**
- While a newer request runs the old results stay on screen (`loading` → `aria-busy`); no skeleton flashes between letters. The first load (no results yet) shows three `Skeleton` rows.
- A failed fetch (not an abort): `error = true`, the panel shows `errors.ACTION_FAILED` quietly in place of the rows; the next keystroke tries again.
- Exposes `setWord`, `toggleTheme(slug)` (one at a time: choosing replaces, choosing the chosen one clears), `setCities`, `showAllHref` (5.7), `reset()`.
- An empty or 1-letter word with no theme still fetches once on open (the idle themes and the place counts), then not again until something changes.

## 13. Risks

- **History with interception.** A result opens a panel by soft navigation (R6). The search's own history entry must be replaced, not left behind; closing the search on the click (instead of on the address change) would make `useBackClose` step back while Next replaces the entry and lose the panel. H1–H9 prove the order; on failure stop (stop point 2).
- **The live URL under a panel** is the panel's (R6 risk): the header field reads discovery's word and place only when the pathname is `/`; under a panel it starts empty and on Visur. Accepted (Default 6).
- **Uncached counts for short words.** `getCounts` with a word loads every matching row (R4 note); a two-letter word matches most groups. Fine at prototype size; if a kind passes a few thousand rows, move the aggregation into SQL (R4's note) and consider a 3-letter minimum.
- **Letters with marks** (Default 10): "speles" finds the Spēles chip but not "Spēļu klubs"; Latvian users often type without marks. Fix later with `unaccent`.
- **Esc order across two listeners** (desktop place list on `document`, search on `window`) relies on `preventDefault` in `FilterPopover`; K8 checks it.
- **Focus trap in a header.** The desktop panel is inside the sticky header; any later `transform` or `filter` on the header would make `fixed` relative to the header and break the panel's place. Keep the header free of them (comment in `Header.tsx`).
- **Session A's edits** to `GroupCard`, `PlaceList`, `PlaceButton` and the panels are in `main` (`263b2bb`, `e57743e`): build on them, keep their behaviour.
