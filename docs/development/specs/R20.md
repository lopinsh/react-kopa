## Invariants (the reviewer checks each)

1. **Behaviour unchanged.** Same hrefs (`discoveryHref(params, …)`, `scroll={false}` on the switch, `limit` dropped on switch), the same chip actions (Kur, Tēma, date, Veidi, "+N", ×, "Notīrīt visu" keeps the switch half), the same "Atbilst arī" logic, the same drawer fold cookie. Only the look, the position and the two counts are new.
2. **Service Law.** The counts come from `DiscoveryService.getCounts` (lib/services). The page reads them, `DiscoveryProvider` carries them and the title reads them via `useDiscovery()`. No Prisma outside services, and no count arithmetic in components.
3. **Context Law.** The title, chips and drawer read state from `useDiscovery()` / `useDiscoveryNav()`. Nothing new is passed down as props except the server-read `folded` (as today).
4. **Taxonomy Law.** A theme chip's tone is its own `--c` from the service colour (as `TopicButton` and the R18 card do). Place, word and date chips set `--c: var(--primary)` (moss). The header alignment is CSS only: no client-side measuring, no `useEffect` layout, and the first paint is already right (the folded state is server-read from the cookie).
5. **One chip family.** Every filter control in the row is 28 px (`h-7`), uses the same text role, `line`, `shadow-control`, `rounded-pill` (the look's control radius), and one chosen style (tint + ×). There is no 32 px pill, underlined link or tray left in the row.
6. **Tone budget.** The title and counts never use a tone (ink and muted only). Moss text appears only on "Notīrīt visu" and the focus ring. Text on a tint is at least 4.5:1 for all 15 tones, light and dark.
7. **Nothing jumps.** `loading.tsx` draws the same rows at the same heights (title line 40, chip row 64, cards from 120), and the column has the same width as the page for the viewer's fold state. When the data arrives, no line moves.
8. **Fluid.** Discovery only: the column sits flush at the left edge, and the board runs from column + `px-gutter` to the right `px-gutter` with no `max-w-browse` centring. Manas grupas and every other page keep their container.
9. **Defaults.** No `any`. Tailwind v4 only, with no inline style except `--c`. Type roles and scale spacing only (`npm run ui:check`). `lucide-react` icons only. Every user-facing string is in both locales.

### 3.2 Title-switch (R20-1)

`TitleSwitch` is a client component. It renders `<nav aria-label={t('viewLabel')}>` holding a flex `items-baseline gap-4 h-10 whitespace-nowrap` row with two `Link`s and a divider span between them.
- Each link uses `text-title` (Literata, fluid 26 to 36; Drosmīgs weight comes from the look token, never from the component). The current one is `text-foreground` with `aria-current="page"`. The other is `text-foreground-muted hover:text-foreground transition-colors duration-quick`. Focus is the site ring (`outline-primary`, offset 3). Href: `discoveryHref(params, { kind, limit: undefined })`, `scroll={false}`.
- The count is a `<span aria-hidden>` inside the link, `ml-1.5 text-meta weight-medium tabular-nums text-foreground-muted`, so it sits on the word's baseline (drawing 348 to 350). The link's accessible name is `t('groupsTab', { count })` / `t('eventsTab', { count })` (section 5). Counts change without animation.
- The divider is `<span aria-hidden className="title-rule">`, a utility in `globals.css`: `width: 1px; height: 0.7em; background: color-mix(in oklab, var(--foreground-muted) 55%, var(--background)); align-self: baseline;` and `@supports (height: 1cap) { height: 1cap }` (the cap-height fallback). It needs the title font on the span, so give the utility `font: inherit` and put `text-title` on the span.
- If the `text-title` line box at 1280 is not 40 px, keep the row `h-10` and align the items to the baseline. Don't add `leading-*`.
- Phones: the same component at the role's small end (26). Under it the chip row follows after 16 (`mt-4` on phones, section 3.5) and the list after 20.

## 4. Data (R20-1)

No schema change and no migration. `getCounts` already answers both kinds, so the service doesn't change.
- In `page.tsx`'s `Promise.all`, add the other kind's counts with the same filters: `DiscoveryService.getCounts({ kind: other, cities: p.cities, l1Slug: p.category ?? undefined, tags: p.tags, query: p.q || undefined, ...(other === 'events' ? w.bounds : {}) }, locale)`. Then `kindTotals = { [p.kind]: counts.total, [other]: otherCounts.total }` goes into `DiscoveryState`.
- On Grupas, `p.date` is `{ kind: 'week' }` (`parseDiscoveryParams`), so the Pasākumi count is this week's. That is exactly what the switch link opens (owner question 3).
- Cost: one extra cached aggregation per filter set (5 min, the existing tags). With a search word it is uncached, like today's main count. If the server timing at `/lv?q=a` grows by more than ~100 ms, report it. Don't optimise in this release.
