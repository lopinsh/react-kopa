## Invariants (must stay exactly as today; the reviewer checks each)

1. **No people for visitors.** A signed-out request (`credentials: 'omit'`) receives no name, image, id or initials of any person in the HTML or the RSC payload, on any page R14 touches. Counts only.
2. **No per-viewer data in a shared cache.** Every `unstable_cache` entry (`discovery.service.ts` 58, `event.service.ts` 936 and 1003, counts) keeps the public, viewer-free shape. Faces are read **outside** these functions, after them, keyed on nothing cached.
3. **Private profiles** (`isProfilePublic = false`) are counted, never shown, except the viewer's own face (`goingFaces`, `event.service.ts` 400).
4. **Members-only events stay hidden** from outsiders (`getEventPage` returns null, `MembersOnlyNotice`); the strip and the next meetup never show a `MEMBERS_ONLY` event to a non-member.
5. **Join behaviour unchanged:** `JoinStep` steps, undo, confirm, waitlist, request, "Pilns", past (R9a invariants 3–8). Only the label of the open "Eju" step gains the count.
6. **Owner text never machine-translated;** `lang` on fallback text (event titles in the strip).
7. **Times:** shown in the viewer's zone via next-intl formatters; "now" never rendered on the client (no hydration drift).
8. **Taxonomy Law:** colours come from the server (`--accent` from the group layout, `--c` from the card's server-resolved `category.color`); no client resolves a colour.
9. **Mierīgs looks as today** apart from the new pieces; Drosmīgs edges come from `line`/`frame` tokens only.

## 0. Motivation and design alignment

- **Kopā = you see who you'd go with.** Faces next to the decision ("Eju") and on the group card make the platform feel peopled; the "Šonedēļ" strip shows that something happens now. Both answer the handbook's "Find → Join" path without new screens.
- **Service Law.** One privacy helper decides whether faces are read; the UI only renders `people: Face[] | null`. `null` = count only (visitor, private group, members-only event); `[]` = signed in but nobody public.
- **Context Law.** The event page reads `EventPageData`, the cards read `GroupCardData`, the group page reads `NextEventView`; nothing prop-drills role or accent.
- **Constants Law.** Face limit stays `FACES_MAX` (`lib/constants/index.ts` 41); the strip limit is a new constant.
- **Reuse.** `FacesLine` keeps its sentence and draws its faces with `Facepile`; `NextMeetingView`, `PictureBox`, `EventRow`'s link behaviour and `getDiscoverableEvents` are reused.

## 2. Data (R14a)

No migration. All in `lib/services/`.

### 2.1 `Face` gains `photo` and `initials` (`lib/services/event-panel.ts` 12, 68)

Additive: `Face = { id; name; image; photo: string | null; initials: string }`. `image` stays (`avatarUrl`, used by other readers); `photo` is the uploaded picture only (null when `image` is empty or a dicebear URL: add `photoUrl(u)` next to `avatarUrl` in `lib/avatar.ts` 14); `initials` = first letters of the first two words of `name ?? username`, upper-cased, at most 2 characters (`lib/avatar.ts`, `initialsOf`). Grep every `Face` reader and keep them compiling.

### 2.2 One privacy rule: `facesAllowed` (new, in `lib/services/faces.ts`, ≤ 60 lines)

```ts
export function facesAllowed(v: { viewerId?: string; groupType: GroupType; eventVisibility?: EventVisibility }): v is { viewerId: string; … }
```
True only when `viewerId` is set, `groupType === 'PUBLIC'` and (no event, or `eventVisibility === 'PUBLIC'`). Used by `getEventPanel` (`event.service.ts` 362), `getEventPage` (392), the next meetup (2.4) and the member faces (2.3). The includes those methods use must select `group.type` (and the event's `visibility`, already there).

### 2.3 Member faces for group cards (`lib/services/faces.ts`)

`memberFaces(groupIds: string[], viewerId?: string): Promise<Map<string, Face[]>>` — empty map when no viewer. One query, never cached:
`prisma.group.findMany({ where: { id: { in: ids }, type: 'PUBLIC' }, select: { id, members: { where: { role: { not: 'PENDING' }, user: { isProfilePublic: true } }, orderBy: { joinedAt: 'asc' }, take: FACES_MAX, select: { user: { select: FACE_SELECT } } } } })` (`relationJoins` is on). Export `FACE_SELECT` from `faces.ts` and reuse it in `goingFaces`.

`toGroupCard` (`group-card.ts` 82) adds `faces: null` (its output may sit next to cached data, so it never holds people). New `withMemberFaces(cards, viewerId)` in `group-card.ts` sets `faces` from the map for signed-in viewers (`[]` for a public group without public profiles, stays `null` for `PRIVATE`; select `type` in `GROUP_CARD_SELECT` and pass it through as `isPrivate`). Call it **after** the cache in:
- `DiscoveryService.getGroups` (`discovery.service.ts` 71): needs the viewer id (the page already has `viewerId`; add the parameter).
- `my-groups.ts` 94/99 and `user.service.ts` 228 (profile groups).
- Not the search rows (`discovery-search.ts`, `GroupRow`): rows keep "N biedri".

Bump no cache key: the cached shape is unchanged (faces are added later).

### 2.4 Next meetup faces (R14b, `event.service.ts` 635–690)

`getNextVisibleEvent` (single group, React `cache`, not `unstable_cache`) returns `NextEventView & { going: { count: number; people: Face[] | null; viewerGoing: boolean } }`: the count from `_count.attendees` (GOING) and `goingFaces` when `facesAllowed`. `getNextVisibleEvents` (many groups, card activity) stays as is: no people.

### 2.5 Week strip data (R14b)

`EventService.getWeekStrip(filters, locale, zone)` (≤ 30 lines, in `event.service.ts` or `lib/services/event-week.ts` if the file grows): calls `getDiscoverableEvents({ ...filters, from, to, limit: WEEK_STRIP_MAX + 3 }, locale)` **without a user id** (public rows only, the cached path), where `from = startOfTodayInRiga()` and `to` = the end of Sunday of this week in `zone` (`mondayOf`, `addDays`, `periodBounds` in `lib/discovery-dates.ts`). Day-rounded bounds keep the cache key stable (a `new Date()` bound would make one entry per request). Drops rows whose `eventTiming` is `past`, returns the first `WEEK_STRIP_MAX` (new constant, `5`). Filters: the page's `category`, `cities`, `tags`; none when the page has a search word (the strip is hidden then).

## 3. `components/ui/Facepile.tsx` (R14a, server-safe, ≤ 70 lines)

Props: `faces: Face[]`, `total: number`, `label: string` (accessible sentence, e.g. "23 biedri"), `size?: 'sm' | 'md'` (20 / 28 px), `more?: boolean` (default true).

- Up to `FACES_MAX` faces, overlapping (`-ml-1.5` / `-ml-2`), each `rounded-full` (handbook Shape: avatars stay full) with `ring-2 ring-surface` to separate them and the `line` edge (1 px soft in Mierīgs, 2 px ink in Drosmīgs).
- A face with `photo`: `<img alt="" referrerPolicy="no-referrer">` (as `FacesLine` today). Without: the `initials` on the category tone, `bg-[color-mix(in_srgb,var(--c,var(--accent))_20%,var(--surface))] text-[var(--c,var(--accent))]`, 11 / 13 px semibold.
- "+N" chip when `more` and `total > faces.length`: same height, `rounded-pill line bg-tint text-foreground-muted`, N = `total − faces.length`, formatted with `useFormatter().number`.
- Wrapper `role="img" aria-label={label}`, children `aria-hidden`. Nothing rendered when `faces` is empty (callers fall back to text).
- `data-ui={UI.facepile}` (add `facepile: 'facepile'` to `UI`, `lib/constants/index.ts` ~253).

Tone outside a group frame: `GroupCard` already sets `--c` (`GroupCard.tsx` 51). `EventPanel` on discovery sets `--c` from `event.category.color` on its root the same way (a server-resolved value; the only inline style allowed is a CSS variable). Inside a group frame `--accent` is set by the layout.

`FacesLine.tsx` keeps its sentence and logic and replaces its `<img>` loop with `<Facepile size="sm" more={false} …>`, so panel and page share one look.

UI elements: add a "Facepile" specimen to `app/[locale]/admin/handbook/ui-elements/page.tsx` (next to `UI.facesLine`, line 185): photos, initials, "+N", signed-out text, in both styles. Sample faces in `lib/handbook/ui-samples.ts`.

## 12. Risks

- **Cache leak (highest).** Adding faces inside `fetchGroupsWithCategories` or `loadPublic` would serve one viewer's people to everyone, signed-out included. Faces are added only after the cached call; reviewer reads every `unstable_cache` call site touched.
- **Query cost.** One extra query per card list (2.3) and one per event page/next meetup; never per card. Check with the Prisma query log on discovery (should be +1).
- **`Face` change.** New fields are additive; a reader that destructures `Face` exhaustively must still compile (typecheck catches).
- **Strip cache key.** Bounds must be day-rounded (2.5); a millisecond `from` defeats the cache and hits the DB on every home view.
- **Container query support** is in Tailwind v4 core; verify the `@4xl` breakpoint (56 rem) in the compiled CSS before relying on it.
- **3:1 crop** of existing 16:9 group pictures cuts top and bottom; `object-cover` centred is the default (the planned banner picker adds focal points later).
