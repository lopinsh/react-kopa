## Invariants (the reviewer checks each)

1. **Zero visual change with defaults.** Unset emphasis (no theme, `type` undefined, `{v:1}`, or a stored `emphasis` equal to the defaults) gives a byte-identical `themeCss()` and the same computed weights as today. Visual baselines: **0 px diff, no PNG updated. Screens to change: none.**
2. **No DB change.** The steps live in the existing `SiteTheme.type` JSON; no migration.
3. **Taxonomy Law:** `--emph-*` are set only server-side by `themeTypeVars` (root `<style>` via `themeCss`) and in the scoped Burti sample (`themeSampleVars`). The panel never writes a CSS variable; it saves the draft and refreshes (R23 §12).
4. **Read-only explain.** R24-1 adds no mutation and no DOM change visible to the page (the probe in §2 is `hidden`, added and removed in the same task).
5. **No per-item overrides.** Emphasis has two site-wide steps; there is no setting per role, per element or per page.
6. **Laws.** Zod as a value only in `lib/validations/`; limits and defaults in `lib/constants/`; no `any`; every save goes through the existing guarded paths (`useDraftSave` in the panel, the Burti editor's draft save); `ui:check` clean.

## 1. Goal and structure (R24-1)

An admin who clicks a text in the Dizains tab learns why it looks as it does: its role, the role's weight, the emphasis on it and what that adds, the computed result, its colour variant and its state. Today the tab says only "Tu noklikšķināji uz varianta „izcelts”" (key `admin.panel.design.variant`); that line is replaced.

Tab structure after a click (`components/admin-panel/DesignTab.tsx` lines ~67-74): role name (`text-item`), **the explain line** (new, `text-meta text-foreground-muted`, replaces the variant line), "Šajā lapā: {count} vietās", then the role editor as today. Choosing a role in the `Select` (no clicked text) shows no explain line.

The line is parts joined with " · ", each present only when it applies:

| Part | When | LV | EN |
|---|---|---|---|
| Role and weight | always (after a click) | `Mazs teksts 400` | `Small text 400` |
| Emphasis | `weight-medium` / `weight-strong` found (§2) | `izcelts +200 → 600` / `vidēji +100 → 500` | `strong +200 → 600` / `medium +100 → 500` |
| Colour | pelēks (§2) | `pelēks` | `muted` |
| State | `aria-current` / `aria-selected="true"` → izvēlēts; `aria-pressed="true"` → nospiests | `izvēlēts` / `nospiests` | `selected` / `pressed` |

No hover and no focus state is named (they are transient; the click itself hovers).

## 2. Reading the text (R24-1)

**Picker.** `useRolePicker` (`components/admin-panel/useRolePicker.ts:6`) passes `{ role, el }` plus `target: Element` (the `e.target` that was clicked). `typeRoleOfElement` (`lib/constants/type-roles.ts:46`) stops collecting a variant: it returns `{ role, el }` only.

**Constants** (`lib/constants/type-roles.ts`, replace `TYPE_VARIANTS` / `TypeVariant` at lines 37-41):

```ts
export const TYPE_EMPHASIS = [
    { key: 'medium', cls: 'weight-medium', cssVar: '--emph-medium', step: 100 },
    { key: 'strong', cls: 'weight-strong', cssVar: '--emph-strong', step: 200 },
] as const;
export type TypeEmphasis = (typeof TYPE_EMPHASIS)[number]['key'];
export const TYPE_MUTED_CLASS = 'text-foreground-muted';
```

`step` is the default (R24-2 makes it a theme setting; R24-1 already reads the effective step from `theme.type?.emphasis?.[key] ?? step`, so R24-2 only adds the schema field). Until R24-2 lands, type `emphasis` access through a small helper `emphasisStep(type, key)` in `lib/theme/type-edit.ts` that returns the default.

**Explain helper:** `components/admin-panel/explainText.ts` (new, client DOM only, <= 60 lines, pure apart from the probe):

`explainText(target: Element, roleEl: Element, utility: string): { base: number; weight: number; emphasis: TypeEmphasis | null; muted: boolean; state: 'current' | 'pressed' | null }`

- **emphasis:** walk from `target` up to `roleEl` inclusive; the first element whose classList holds a `TYPE_EMPHASIS[].cls` wins. Stop at `roleEl`: above it the role utility sets its own weight, so an outer emphasis class does not reach the text.
- **weight:** `Number(getComputedStyle(target).fontWeight)` (the computed one, so `<strong>`, a heavier role override and the clamp at 1000 all show truthfully).
- **base (the role's own weight in this place):** a probe `span` with `hidden` and only `className = utility`, appended to `roleEl.parentElement`, read `getComputedStyle(probe).fontWeight`, removed at once (computed style works on `display:none`; it inherits the same vars, sample scope and heading weight as the real text). Do not try to read `--role-weight`: unregistered custom properties compute to the token string (`calc(500 - 100)`), not a number.
- **muted:** walk from `target` up to `document.body`; the nearest element holding `text-foreground` or `text-foreground-muted` decides; muted when it is `TYPE_MUTED_CLASS`.
- **state:** `target.closest('[aria-current]:not([aria-current="false"]), [aria-selected="true"]')` → `current`, else `target.closest('[aria-pressed="true"]')` → `pressed`, else null.

The emphasis part shows the **effective step** from the theme and the **computed weight**. For roles whose emphasis starts below the role weight (button −100, tag −200; `app/globals.css:214-232`), base + step will not equal the result ("Poga 500 · izcelts +200 → 600"): that is the truth of the CSS and the line shows it as is (Owner question 1).

## 3. Keeping it current (R24-1)

`DesignTab` keeps `picked: { target, el, utility } | null` in state (set on pick, cleared when the `Select` changes or the role clears). The explain result is computed in an effect keyed on `[picked, designTheme]`: `designTheme` changes when the refreshed server payload (with the new root `<style>`) commits, so after a role or emphasis step the numbers follow. If `!picked.target.isConnected` (client navigation, re-render replaced the node) the line disappears and the role stays selected.

Keep `DesignTab` under ~150 lines: the line renders in a new `components/admin-panel/TextExplain.tsx` (<= 60 lines; R24-2 adds the emphasis row to it).

## 5. Goal and data (R24-2)

The two emphasis steps become a site theme setting. `app/globals.css:238-243` today adds a literal 100 / 200 to `--role-weight`; it reads a variable instead, with the literal as the fallback, so an unset theme computes the same weight.

**Constants** (`lib/constants/type-roles.ts`, next to `TYPE_EMPHASIS`):

```ts
export const TYPE_EMPHASIS_LIMITS = { min: 0, max: 400, step: 100 } as const;
```

**Schema** (`lib/validations/theme.ts`, `themeTypeSchema` at line ~33), one optional key:

```ts
emphasis: z.object({
    medium: z.number().int().min(TYPE_EMPHASIS_LIMITS.min).max(TYPE_EMPHASIS_LIMITS.max).multipleOf(TYPE_EMPHASIS_LIMITS.step).optional(),
    strong: /* same */,
}).refine((e) => (e.medium ?? 100) <= (e.strong ?? 200)).optional(),
```

The `100` / `200` read from `TYPE_EMPHASIS` (find by key), not literals. No migration (invariant 2); the stored JSON stays sparse.

## 6. CSS and vars (R24-2)

- `app/globals.css` `weight-medium`: `font-weight: min(calc(var(--role-weight, 400) + var(--emph-medium, 100)), 1000);` and `weight-strong` with `--emph-strong, 200`. Update the comment above (line ~236): the steps are theme settings (Burti > Izcēlums), the literals equal `TYPE_EMPHASIS`. `--role-weight` and its per-role offsets stay exactly as they are.
- `lib/theme/type-vars.ts` `themeTypeVars` (line ~69): for each `TYPE_EMPHASIS` entry, emit `vars[cssVar] = String(value)` **only when** `type.emphasis?.[key]` is set and differs from `step`. Values are validated integers; no `snapWeight` (the sum is computed by the browser, which picks the nearest face).
- `typeDefaultVars` (line ~38): add `--emph-medium: 100`, `--emph-strong: 200` so the scoped Burti sample (`themeSampleVars`, `lib/theme/css.ts:154`) shows the draft, not the published steps. The root path (`themeCss`, `lib/theme/css.ts:143`) does not call `typeDefaultVars`, so it stays byte-identical.
- `lib/theme/type-edit.ts` `patchType` (line ~43): drop `emphasis.medium` / `.strong` equal to their default and drop `emphasis` when empty, so a page stepped back to +100 / +200 stores what it stored before. `emphasisStep` (R24-1) now reads `type?.emphasis?.[key] ?? default`.

## Risks

- **Concurrent edits.** `docs/handbook/design.md` and `components/discovery/lists/CategoryRow.tsx` had uncommitted changes from another builder when this spec was written. Stage your hunks by explicit path (`git add -p` is interactive and unavailable: commit the handbook only if its diff is yours alone, else leave the handbook line for the orchestrator and say so). If `.git/index.lock` exists, wait and retry.
- **Blue/green.** During a deploy the old app parses the theme with the old schema, which strips `emphasis`; a save made on the old app in that window drops it. Prototype stage: accepted.
- **Hover weight.** The computed weight is read while the pointer is over the text; a `hover:` weight change would show up. None is used for weight today (grep `hover:weight`); if one appears, read before the hover by using `pointerdown`, not a new rule.
- **Probe in odd parents.** A `roleEl` whose parent is an SVG or a `<select>` cannot hold a `span`: if `parentElement` is not an `HTMLElement` or append throws, fall back to `base = weight` when no emphasis was found and omit the role weight number otherwise.
- **Font faces.** A step can ask for a weight the font lacks (e.g. 700 in a 400-600 family); the browser picks the nearest face. The line shows the computed request, not the face; acceptable for an experiment tool (handbook: Admin > Dizains may go outside the limits).

## Owner questions (the builder uses the default unless the owner objects)

1. **Buttons and tags: base + step does not add up** ("Poga 500 · izcelts +200 → 600", because their emphasis starts from the role weight minus 100 / 200 to keep today's look). Default: show the computed truth as is; no correction text.
2. **The panel's Izcēlums row: both steppers, or only the one the clicked text uses?** Default: both (the limits couple them, and vidēji ≤ izcelts is clearer side by side).
3. **Emphasis inside heading roles** starts from 400, not the heading weight (headings set no `--role-weight`). Default: leave as today (out of scope); a later release can give headings a `--role-weight` if the owner wants emphasis to follow the heading weight.
