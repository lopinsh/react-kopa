# R18 spec · Ziņojumu dēlis group cards

Just-in-time spec for release R18 (not in the closed [build plan](../build-plan.md); the owner asked for it after the redesign closed), written 22 Oct 2026 against `main` at `c8cdf3b`, Next.js 16, Tailwind v4. Owner-approved drawing: [`../r18-group-cards.html`](../r18-group-cards.html) (committed with this spec). Frozen once R18 is pushed.

**Problem.** The group card is a plain stack (photo, text, thin line, note). The owner wants the board metaphor: each group is a note pinned to a **Ziņojumu dēlis** (notice board). Two touches carry it and nothing else: a **sticker** (the category, slightly tilted, over the photo's bottom edge) and a **tear-off tab** (the card's bottom, with a perforation and scissors, tinted). No cork, pins, tape, handwriting or paper grain (the drawing's "Ko nedarām", section G).

**Rules touched.** [AR-34](../redesign.html#AR-34) Group card (desktop), [AR-36](../redesign.html#AR-36) Group row (phones), [AR-37](../redesign.html#AR-37) Create card, [AR-35](../redesign.html#AR-35) "Ko meklējam?" (fallback note), [AR-06](../redesign.html#AR-06) Colour means category (the tab tint is a "soft tint", see section 7), [AR-09](../redesign.html#AR-09) role tags (unchanged), [AR-08](../redesign.html#AR-08) shapes and [AR-07](../redesign.html#AR-07) fonts (unchanged). Rule text: `scripts/redesign/gen.mjs` 93, 123 to 126. The drawing is an illustration at 375 and 1280 px (AGENTS.md): build the intent, fluid between and beyond.

**Drawing source (read these, never restate them).** `docs/development/r18-group-cards.html`: CSS 100 to 135 (`.role`, `.sticker`, `.band`, `.stub`, `.tear`, `.snip`, `.when`, hover block); section E "Telefon: rindas variants" lines 375 to 395 (row spec); section F "Anatomija" lines 397 to 417 (the eleven parts); section G "Stilu grāmata" from line 418 (type, colour, spacing, motion tables, "Toņa budžets" line 459). Hard-coded drawing values (px sizes) map to the nearest scale step or existing token; the numbers below are the intent.

**No DB, service, action or schema change.** Props and data of `GroupCard`, `GroupRow`, `CreateCard` stay as they are.

## Invariants (the reviewer checks each)

1. **Data and links unchanged.** Same props, same stretched name link (`data-card-link`, `data-opens-panel`, `data-panel-origin`), `fullPage` plain link, `highlight`, `searchItem`/`replace` on rows, `data-ui` markers (`UI.groupCard`, `UI.groupRow`, `UI.createCard`), same panel origin animation.
2. **Link layering.** Name link `::after` covers the card; above it (`relative z-[2]`): sub-category links, the **sticker (a link to the L1 filter, like the category link today, `aboveCardLink`)**, the Team `requestCount` link. The role pill is a plain tag, not a link, stays on the photo (top right).
3. **Taxonomy Law.** Tones come from `--c` set on the card (`style={{ '--c': group.category.color }}`), as today; no client-side accent. `--accent` is never used for the tab.
4. **Colour means category (AR-06).** Tone appears only on: the dot, the category icon, the tab tint, the no-photo band tint and glyph pattern, the "when" icon. The perforation, scissors and text are neutral. The site colour (`text-primary`) is used for links and nothing on the tab but the `requestCount` link and the "Notiek tagad" pulse (see 3.3).
5. **Contrast.** Text on the tab tint (12 % light, 16 % dark of the tone over `--surface`) is at least 4.5:1 in all looks and modes; the note is `text-foreground`, the place line `text-foreground-muted`. Tone-coloured text is not used on the tab.
6. **Even rows.** A grid row keeps one card height, as today: name `min-h-[2lh]` (2 lines), tagline 2 lines reserved, **tab fixed height** (two rows), also when there is no note. The CreateCard in a grid and in a list has the same tab height.
7. **Motion.** Hover and the sticker's tilt-to-zero are behind `motion-safe:`; reduced motion shows the resting state, no transition. Nothing moves on touch (hover only, `@media (hover: hover)`).
8. **No new vocabulary on the board.** Category line stays a `CategoryLine` (dot, L1, sub-categories as links) where it exists (section 3.1), role tones unchanged, `Faces` stays the one faces atom.
9. **Defaults.** No `any`; Tailwind v4 only, no inline style except the `--c` variable; type roles and scale spacing only (`npm run ui:check`).

## 1. Who sees what (R18-1 and R18-2)

The tab's second row depends on the viewer; the first row (the note) does not.

| Viewer / state | Row 1: note | Row 2: left | Row 2: right |
|---|---|---|---|
| Visitor, not a member | note | faces only if the page already passes `faces` (signed-in only today); a visitor has none, so: empty seat only | place, members |
| Signed in, not a member | note | up to 3 faces + "+N" if `faces`, then the empty seat | place, members |
| Member (any role, incl. Team) | note | faces, **no seat** | place, members |
| Pending ("Gaida") | note | faces, then a **clock seat** (dashed circle with a `Clock` icon, aria "Pieteikums gaida") | place, members |
| Team with `requestCount > 0` | note stays one line; the request link replaces nothing in the tab: it keeps its own line **above the tab** under the tagline (`min-h-[2lh]` block as today, section 3.1) | as member | |

Row 1 note priority (one line, `truncate`, the full text is in the opened panel): running meeting ("Notiek tagad" with the pulse dot), next meeting (`meetingLine`), newest public announcement, `lookingFor`; none of them: row 1 is empty and the people row is centred vertically in the tab (the drawing's "bez piezīmes cilvēku rinda centrēta"). The tab is drawn in every case (even rows); this replaces "no activity, no line".

Seat visibility reuses the viewer's role already known to the card: `role` (set in Manas grupas; `RoleTag` logic) or `showMember` on discovery. No new fetch: on discovery a signed-in non-member is `role === undefined`, a member is `role` set. If a page passes no `role` for a member (check callers in `GroupResults`, `GroupList`, own-area lists with `grep -rn "<GroupCard\|<GroupRow"`), the seat shows for them, which is wrong: the builder lists callers in the commit message and passes `role` wherever missing (default: the callers that render Manas grupas already do).

## 3. Structure

### 3.1 Card (R18-1, commit 2)

Top to bottom, inside the existing card shell (`rounded-2xl line bg-surface shadow-card`, `overflow-hidden` is **removed from the shell** because the sticker overlaps the photo edge inside it; put `overflow-hidden` on the photo box and the tab instead):

1. **Photo 5:2** (as today), role pill top right (unchanged), faces chip on the photo **removed** (faces move to the tab; the photo chip token `--photo-chip` stays in use elsewhere, do not delete it).
2. **No photo:** a slim tone band (about 64 px: `min-h-16`) with the category glyph pattern behind and the L1 icon + L1 name in front, role pill vertically centred right (as today). Band tint is the no-photo band utility (section 4). The sticker is **not** drawn on a no-photo band (the band already says the category); the sub-categories line stays.
3. **Sticker** (photo cards only): `Link` to the L1 filter (`/?category=<l1Slug>` merged with `filters`, same href logic as `CategoryLine` for L1; reuse its helper, do not rebuild the query), tone dot + `category.l1Title`, left 16 px (`left-4`), straddling the photo's bottom edge (about half below), own opaque `bg-surface` base and edge, `-2deg` tilt, `motion-safe` hover to 0deg. It must read on white, black and busy photos ("Grūtas bildes", section D of the drawing): opaque base is the rule. Name `max-w` keeps it inside the card, truncates.
4. **Body:** reserve room under the sticker (`pt-6`/scale step, check at 1920). Title (`text-item`, serif role as today, 2 lines reserved), then the **sub-categories line** as `CategoryLine` showing sub-categories only (the L1 is now the sticker; on no-photo cards the L1 is in the band, so the same). Add a `CategoryLine` prop or a new `subOnly` variant; keep `oneLine`/`aboveCardLink`. Then the tagline (2 lines reserved). City and member count **leave the body** (they are in the tab's row 2).
5. **Tab** (`GroupCardActivity`, always rendered): perforation line across the top (neutral, section 4), scissors at the left end, tinted fill below, padding `--card-pad`.
   - Row 1: icon (`CalendarDays` meeting, `Megaphone` announcement, `Megaphone` for lookingFor too) + note text, one line, ellipsis. "Notiek tagad": pulse dot + text, `motion-safe:animate-pulse`.
   - Row 2: `Faces` (28 px, overlap 8 px, up to three) + "+N" for the rest, then the seat (dashed ring, `Plus`, aria "Vieta tev"), flexible gap, then `city · N members` as `text-meta text-foreground-muted`, `truncate`, never wraps.
6. **Team request link:** with `requestCount > 0` it sits between tagline and tab, `text-meta weight-strong text-primary`, relative z-[2]; the tagline is then 1 line (as today's `min-h-[2lh]` block). Rows stay even because that block reserves 2 lines.

Props: `GroupCardActivity({ activity, lookingFor, faces, memberCount, cityLabel, seat })` where `seat: 'open' | 'pending' | 'none'` is computed in `GroupCard` from `role` and `showMember` (section 1). Keep it a server-renderable component (no `use client`).

### 3.2 Row, phones (R18-2, commit 4)

Source: drawing section E lines 375 to 395. Layout, left to right, row `min-h-[5.5rem]`-ish by content, dashed divider between rows (`border-t border-dashed border-border`, a divider, so `border-border` is allowed):

- **Thumb** 56 px (`size-14`), `rounded-item`-class radius via the shape token (not a hard-coded 14 px): the photo (`next/image`, `sizes="56px"`, `object-cover`) or, without one, a `cat-tile` with the L1 icon. Decorative (`alt=""`).
- **Text column** (name link stretched, as today): name `text-item`, **one line** (truncate; the 2-line name of AR-36 is changed by this release: owner approved a single-line name in the drawing), category line (dot, L1, then sub-categories, `truncate`; sub-categories give way first), then the **mini tab chip** below, full column width: tinted, `rounded-item`, **no perforation and no scissors** (noisy at this size), one line: the note if there is one, else `city · N members`. A running meeting shows the pulse. Chip height fixed (one text line plus padding) so rows are even when there is no note.
- **Right edge:** the empty seat (same rules as section 1: not for members; clock seat for Gaida) or, in Manas grupas, the `RoleTag` in its place (as today, role before nothing else; a member with no tag shows nothing). Team `requestCount` link stays under the chip as today (`text-tag text-primary`).
- The tagline is **not** shown in the row (the chip takes its place; the drawing drops it). Faces are not shown in the row.

Row has no sticker and no perforation. The role pill never overlaps the thumb.

### 3.3 Tone, per look (state in every look; all three must be checked)

The look is the style key (`calm` Mierīgs, `bold` Drosmīgs, `airy` Gaisīgs) from `lib/constants/theme.ts`. The tab tint, band tint and glyph pattern use their own new variables, so the Mierīgs numbers hold for all and each look overrides only what it must:

| | Mierīgs (calm) | Drosmīgs (bold) | Gaisīgs (airy) |
|---|---|---|---|
| Tab tint | tone 12 % light / 16 % dark over `--surface` | same (a tint, not the bold solid tile: the tab holds text and faces, solid would break contrast 4.5:1 for the note) | same |
| No-photo band | tone 24 % light / 30 % dark + glyph pattern at about 22 % opacity | solid tone allowed by `--tile-mix` (100 %) with `--tile-on` ink, pattern in the ink colour at low opacity | 24 / 30 % as Mierīgs, thinner glyph stroke (`--icon-stroke`) |
| Edges of card, sticker, seat, role | `line` (soft) | `line` becomes the 2 px ink; sticker and seat take it too; sticker gets `shadow-control` (hard offset) instead of the soft shadow | thin soft line as Mierīgs |
| Perforation | neutral muted dashes, 2 px | **ink-coloured** dashes, 2 px (`--line-color`, the style's line colour); still no tone | muted, 1 px |
| Scissors | muted, 16 px | ink, 16 px | muted, thin stroke (`--icon-stroke`) |
| Corners | `rounded-2xl` card (`--radius-*` tokens) | small corners from the style; the tab follows the card's bottom radius (use the card's radius token, do not hard-code) | large soft corners from the style |
| Tilt | -2deg | -2deg | -2deg |

Rule for builders: use the existing tokens (`--radius-*`, `--line-width`, `--line-color`, `--shadow-*`, `--tile-mix`, `--tile-on`, `--icon-stroke`, `--card-pad`); never read the style key in a component. In bold the hard shadow of the card needs `shadow-room` in clipping parents (already in the lists).

### 3.4 CreateCard (R18-1, commit 3)

Same outer shape as `GroupCard` (dashed edge kept: `border-dashed` is the "start something here" sign; the style's line colour in bold), centred round `+` and the two lines as today in the upper part, and **the same fixed-height tab** below with perforation and tint, holding `inThisCategory` centred in row 1 and nothing in row 2. The tab uses the discovery category's tone (`--c` from the chosen L1) when one is chosen (it always is: AR-37). `variant="row"` (phones): same height as a group row, dashed bottom divider, the round `+` right where the seat is, no thumb (a 56 px dashed tile with `+` in the thumb's place, default; the seat position is then empty). Keep `data-ui`, `href`, link semantics. In a grid it must be as tall as its neighbours: `h-full` with the tab fixed, the upper area flexible.

## 4. CSS (R18-1, commit 1)

In `app/globals.css`, near `cat-tile` (line ~344), as `@utility` blocks with `--c` required on an ancestor, no look values hard-coded other than the two tint shares:

- Tokens (in `:root` and `.dark`, i.e. wherever the mode tokens live): `--tab-mix: 12%` (light), `16%` (dark); `--band-mix: 24%` (light), `30%` (dark). Bold overrides `--band-mix` through the existing `--banner-mix` mechanism: reuse `--banner-mix` for the band (calm 12 % there is the group page banner, so the band gets its own `--band-mix`, and `lib/theme/css.ts` sets it to `100%` when `style.tile === 'solid'`, else leaves the default; one added line, no new style field).
- `tab-tint`: `background-color: color-mix(in srgb, var(--c) var(--tab-mix), var(--surface))`.
- `band-tint`: `color-mix(in srgb, var(--c) var(--band-mix), var(--surface))`; text `color-mix(in srgb, var(--c) 70%, var(--foreground))` in calm and airy (check 4.5:1 on all 15 tones, light and dark: tones with the lowest contrast first), the existing `tile-ink` in bold.
- `glyph-pattern`: a repeating inline SVG data-URI `background-image` of the category pattern (drawing line 568 shows the pattern construction: diamond path, stroke `--c`, opacity .22). One generic pattern for all categories is fine; do not draw 15 patterns (default).
- `perforation`: a pseudo-element or `border-top: var(--line-width, 2px) dashed` is **not** enough (the drawing has dash 9/gap 6 with round caps): use `background-image: repeating-linear-gradient` for the dashes or a data-URI SVG with `stroke-dasharray`, coloured `color-mix(in oklab, var(--border), var(--foreground-muted) 30%)` (calm, airy) and `var(--line-color)` (bold). The line stops 4 px before and after the scissors' gap (left gap about 36 px).
- `tear-scissors`: positions the lucide `Scissors` at the left end of the tab, `-top-3` straddling the line; a `size-4` icon in `text-foreground-muted/70`.
- `sticker`: `rotate(-2deg)`, origin left centre, `motion-safe:transition-transform`, hover (parent `group` or `:hover` on the card inside `@media (hover:hover)`) to 0.
- Hover on the tab (`motion-safe`, hover-capable only): scissors slide 12 px right, the perforation stays continuous (gap grows with them), the line turns `--foreground-muted`, the tab drops 1 px. Duration 240 ms, `cubic-bezier(.2,.7,.2,1)` (style book "Kustība"; check the existing motion token before adding a curve).

Utilities are named by what they are (`tab-tint`, `band-tint`, `glyph-pattern`, `perforation`, `sticker`), not by the release.

## 9. Risks

- **Seat for members.** If a list passes no `role` for a member, the seat appears wrongly (section 1). Mitigation: audit callers in commit 2.
- **Overflow and the sticker.** The shell loses `overflow-hidden`; make sure the photo and tab clip their own corners and the hard shadow in bold is not clipped by a parent.
- **Link layering.** The sticker is a second link on a stretched-link card: z-index and keyboard order are the main failure mode (invariant 2).
- **Contrast of band text** on mid-light tones in dark mode at 30 %.
- **Row name to one line** drops information AR-36 allowed (2 lines); the panel shows the full name. Owner approved via the drawing.
- **Data URI pattern** cost and CSP: inline `data:` images must be allowed by the current CSP (`grep -rn "img-src" next.config.ts`); if not, use a CSS gradient pattern.
- **Looks drift:** a component reading a style key instead of tokens; reviewer greps for `styleKey` in `components/discovery`.
